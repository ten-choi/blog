# 7.6 Mobility Management in Practice

<br/>

## 7.6.1 Mobility Management in 4G/5G Networks

> Let's look at which elements work together, and how, to support mobility in today's 4G/5G networks.

Consider a scenario where a user in a car connects to a visited 4G/5G network with a smartphone, starts streaming HD video from a remote server,  
and then **moves from one 4G/5G base station's cell to another's**.

<br/>

<p align="center"><img width="600" alt="Mobility scenario" src="https://user-images.githubusercontent.com/86337233/216887701-4c7e6f31-d870-4879-8be4-9bb5396a54e3.jpg">

<br/>
<br/>

1. Mobile device and base station association
    - The mobile device associates with a base station in the visited network.


2. Control-plane configuration of network elements for the mobile device
    - The visited and home networks set up control-plane state indicating that the mobile device is in the visited network.


3. Data-plane configuration of forwarding tunnels for the mobile device
    - Using indirect routing through the home network's PDN gateway, the visited and home networks set up tunnels  
      through which the mobile device and the streaming server can send and receive IP datagrams.


4. Mobile device handover from one base station to another
    - The mobile device changes its point of attachment to the visited network via handover from one base station to another.

<br/>

### 1️⃣ Base station association

1. The mobile device gradually learns more about the base stations around it.
    - It listens across all frequency bands for the primary signals transmitted by base stations in its area.


2. The mobile device eventually picks a base station to **associate** with and sets up an initial control signaling channel with it.
    - As part of association, the device provides the base station with its home network information, other subscriber information, and its IMSI (unique identifier).

<br/>

### 2️⃣ Control-plane configuration of network elements for the mobile device

Once the signaling channel between the mobile device and the base station is set up, the base station can contact the visited network's `MME`.

The MME consults and configures various 4G/5G elements in both the home and visited networks to set up state on behalf of the mobile node.

- The MME uses the IMSI and other information provided by the device to retrieve the subscriber's authentication, encryption, and available network service information.
    - That information may be in the MME's local cache, retrieved from another MME the device recently contacted, or retrieved from the HSS in the device's home network.
- The MME notifies the `HSS` in the home network that the mobile device is now in the visited network, and the HSS updates its database.
- The base station and mobile device select parameters for the data-plane channel to be set up between them. (The control-plane signaling channel is already up.)

<br/>

### 3️⃣ Data-plane configuration of forwarding tunnels for the mobile device

The MME configures the `data plane for the mobile device` as shown below.

<br/>

<p align="center"><img width="600" alt="Tunneling" src="https://user-images.githubusercontent.com/86337233/216887710-4548ee72-10d6-45bd-8f32-2d6f666a7339.jpg">

<br/>
<br/>

Two tunnels:

1. Between the base station and the visited network's serving gateway
2. Between that serving gateway and the PDN gateway router in **the mobile device's home network**

→ 4G LTE implements this form of symmetric indirect routing.

<br/>

All traffic to and from the mobile device is `tunneled` through the device's home network.

<br/>

4G/5G tunnels use the `GPRS Tunneling Protocol (GTP)`.

The `TEID (Tunnel Endpoint ID)` in the GTP header indicates which tunnel a datagram belongs to, so GTP can multiplex and demultiplex multiple flows between tunnel endpoints.

<br/>

### 4️⃣ Mobile device handover from one base station to another

A `handover` happens when a mobile device **changes its association** from one base station to another.

<br/>

- Datagrams to and from the mobile device are initially (before the handover) delivered via the base station it's currently associated with (the **source** base station).
- After the handover, they're routed to the device via another base station (the **target** base station).

<br/>

A handover between base stations doesn't just mean the mobile device now talks to a new base station;  
on the network side it also means a change to the serving-gateway-to-base-station tunnel.

<br/>

The mobile device periodically measures `the beacon signal from its current base station` and `the signal characteristics of nearby base stations it can hear`.

These measurements are reported to the device's current (source) base station once or twice a second,  
and **based on those measurements, the load on nearby cells, and other factors, the current base station may decide to initiate a handover.**

<br/>

The figure below shows the handover procedure from the mobile device's source base station to the target base station.

<br/>

<p align="center"><img width="600" alt="Handover" src="https://user-images.githubusercontent.com/86337233/216887712-02ebc640-42fc-4dfa-98ab-172886039029.jpg">

<br/>
<br/>

1. The current (source) base station selects a target base station and sends it a `Handover Request message`.


2. (1) The target base station checks whether it has enough resources to support the mobile device and its quality-of-service requirements.

   (2) If so, it pre-allocates radio access network channel resources (e.g., time slots) and other resources for the device.

   (3) The target base station replies to the source base station with a `Handover Request Acknowledge message`, which contains all the information the mobile device needs to associate with the new base station.


3. The source base station receives the Handover Request Acknowledge message and tells the mobile device `the target base station's ID and channel access information`.
    - At this point the mobile device can start sending and receiving datagrams with the new target base station. (In other words, from the device's point of view the handover is done.)
    - From the network's point of view, there's still a bit more work to do.


4. (1) The source base station stops forwarding datagrams to the mobile device and instead forwards the tunneled datagrams it receives to the target base station.

   (2) The target base station later delivers those datagrams to the mobile device.


5. (1) The target base station tells the MME that it will be the new base station serving the mobile device.

   (2) The MME in turn signals the serving gateway and the target base station to  
   reconfigure the serving-gateway-to-base-station tunnel so that it terminates at the new (target) base station instead of the old (source) one.


6. The target base station confirms back to the old (source) base station that the tunnel has been reconfigured,  
   allowing the old base station to release the resources associated with the mobile device.


7. At this point the target base station can also start delivering datagrams to the mobile device  
   (including the datagrams forwarded from the source base station during the handover).

   It can also receive outgoing datagrams from the mobile device and send them through the tunnel to the serving gateway.

<br/>

The roaming configuration of today's 4G LTE networks is expected to carry over to future 5G networks,  
but 5G networks will be much denser, with much smaller cells.

So for many real-time 5G applications, **short handover times** will become critical.

It's believed that moving the cellular network control plane onto an `SDN framework` (Chapter 5) could enable a high-capacity, low-latency 5G control plane.

<br/>

## 7.6.2 Mobile IP

Today's Internet has no widely deployed infrastructure that provides the kind of service **for users "on the move"** that we saw in 4G/5G cellular networks.

However, the `Mobile IP architecture and protocols` have been standardized as Internet RFCs for over 20 years, and research continues on new, more secure, and more general mobility support.

<br/>

### Similarities between the 4G/5G and Mobile IP architectures

<br/>
<br/>

### The three main parts of the Mobile IP standard

> ✅ Agent discovery

Mobile IP defines the protocols a `foreign agent` uses to advertise mobility services to mobile devices that want to attach to its network.

These services include providing a `care-of address (COA)` for the mobile device to use in the foreign network,  
registering the device with the home agent in its home network, forwarding datagrams to and from the device, and other services.

<br/>

> ✅ Registration with the home agent

Mobile IP defines the protocols used by the mobile device and the foreign agent to register and deregister a COA with the device's home agent.

<br/>

> ✅ Indirect routing of datagrams

Mobile IP defines how datagrams are forwarded to the mobile device by the home agent.

This includes rules for forwarding datagrams and handling errors, as well as several forms of tunneling.
