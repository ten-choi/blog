# 8.5 Securing E-Mail

Security services can be provided at any of the top four layers of the Internet protocol stack.

When security is provided for a specific application-layer protocol, applications that use that protocol get to use the security services.

<br/>

### Why security is provided at more than one layer

Wouldn't it be enough to provide security at the network layer?

1. Even if the network layer provides "blanket coverage" by encrypting all the data in datagrams and authenticating IP addresses, it can't provide user-level security.
    - For example, an e-commerce site can't rely solely on IP-layer security to authenticate a customer who wants to buy something.
2. It's becoming increasingly easy to implement new Internet services, including security services, at the higher layers of the protocol stack.

<br/>

## 8.5.1 Secure E-Mail

Let's use the principles of cryptography to build a secure e-mail system.

<br/>

### Confidentiality

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217525558-f8e45897-3701-4630-bb11-cb8b78d42edf.png" alt="Confidentiality"></p>

Confidentiality can be achieved by encrypting and decrypting the message with symmetric key technology (AES, DES, etc.).

But since it's hard for only the sender and receiver to share a symmetric key, we turn to public key encryption (RSA).

<br/>

However, encrypting and decrypting the message with RSA alone is too computationally expensive to be practical.

So we use a session key.

1. The sender picks a random **symmetric session key Ks**.
    - This symmetric session key is used with AES or DES.
2. Encrypt the message m with Ks to get ciphertext 1.
3. Encrypt Ks with the receiver's public key to get ciphertext 2.
4. Send both ciphertexts to the receiver.
5. The receiver decrypts ciphertext 2 with its private key to get Ks.
6. It uses Ks to decrypt ciphertext 1 and get m.

<br/>

That gives us confidentiality.

<br/>

### Sender authentication and message integrity

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217525553-ee567afd-d3ba-4ae7-a883-52421b55fd0e.png" alt="Authentication"></p>

To get both of these, we use a digital signature and a hash algorithm.

1. The sender applies a hash function to m to get a message digest, H(m).
2. To create the digital signature, the sender encrypts the hash result with its private key.
3. Send the message m and the digital signature to the receiver.
4. The receiver decrypts the digital signature with the sender's public key.
5. It compares the result of applying the hash algorithm to m with the result of step 4; if they match, the sender and the integrity of the message are verified.

<br/>

### Putting it together

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217525541-71da564f-6b9d-4b60-a9b8-10c199e5bcc7.png" alt="Putting it together"></p>

1. First, build a package of the message and the digital signature obtained through the sender authentication and integrity process.
2. Treat this package as a single message and deliver it to the receiver through the confidentiality process.
3. The receiver decrypts and verifies in order.

However, the receiver needs to know the sender's public key and the sender needs to know the receiver's, so the public keys must be certified by a CA.

<br/>

## 8.5.2 PGP (Pretty Good Privacy)

PGP is a good example of these cryptographic techniques and is essentially the same as the combined scheme above.

1. When PGP is installed, the software creates a public key pair for the user.
    - The public key is posted on the user's website or placed on a public key server.
    - PGP public keys are certified within a `web of trust` among users.
    - Some PGP users hold key-signing parties, gathering in the same physical space to exchange public keys and vouch for each other's keys by signing them with their private keys.
2. The private key is protected by a password.
    - To use the private key, the user has to authenticate with the password.
3. As with the e-mail scheme above, PGP gives the user the option to digitally sign a message, encrypt it, or both.
    - With a private key, a public key, a hash algorithm, and RSA, all of these are possible.
