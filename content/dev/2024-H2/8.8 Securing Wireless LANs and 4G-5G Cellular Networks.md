# 8.8 Securing Wireless LANs and 4G/5G Cellular Networks

## 8.8.1 Authentication and Key Agreement in 802.11 (Wi-Fi) Wireless LANs

### Key Security Concerns in 802.11 Networks

- Mutual authentication
    - Before a mobile device can attach to an AP and send datagrams out, the network wants to authenticate the device to verify its identity and check its access privileges.
    - The mobile device, in turn, wants to authenticate the network to make sure it's really the network it intends to join.
    - This two-way authentication is called **mutual authentication**.
- Encryption
    - Since 802.11 frames are exchanged over a wireless channel, it's important to encrypt the link-level frames carrying user-level data between the mobile device and the AP.
    - Symmetric-key encryption is used because high speed is required.

<br/>

### Mutual Authentication and Encryption Key Generation and Use

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/218796266-8169a7a8-e4db-4d88-a283-ee029bd2726f.png" alt="Procedure"></p>


1. Discovery
    - The AP advertises its presence along with the forms of authentication and encryption it can offer to mobile devices.
    - The mobile device requests the forms of authentication and encryption it wants.
2. Mutual authentication and shared symmetric key derivation
    - We assume the authentication server and the mobile device already have a **shared common secret**.
    - The mobile device and the authentication server use this shared secret, along with nonces and cryptographic hashing, to authenticate each other.
    - They also derive the shared session key that will be used to encrypt frames sent over the wireless link between the mobile device and the AP.
3. Shared symmetric session key distribution
    - Since the symmetric secret key is derived at the mobile device and the authentication server, a protocol is needed for the authentication server to inform the AP of the shared symmetric session key.
4. Encrypted communication between the mobile device and a remote host via the AP
    - Communication takes place using link-layer frames encrypted with the session key derived and distributed in steps 2 and 3.
    - The AES symmetric-key algorithm is used to encrypt and decrypt the frame data.

<br/>

### Mutual Authentication and Shared Symmetric Key Derivation

WEP, the original 802.11 security specification, had serious security flaws, and WPA1 was developed to overcome them.

WPA1 introduced message integrity checks and protection against attacks that guess the encryption key by observing the encrypted message stream over a period of time.

WPA2 improved on WPA1 by mandating AES symmetric-key encryption.

<br/>

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/218796256-1bbfc9c3-d8a0-4db0-babd-44c69a83f6d2.png" alt="Mutual authentication and shared symmetric key"></p>


The figure above shows a simplified four-way handshake protocol.

Both sides start out knowing a shared secret key (e.g., a password).

1. The authentication server generates a nonce and sends it to the mobile device.
2. The mobile device receives the nonce from the AS and generates its own nonce. The mobile device then **derives the symmetric shared session key using its own nonce, the received nonce, the initial shared secret key, the mobile device's MAC address, and the AS's MAC address**. It then sends its own nonce along with an HMAC-signed value computed over the received nonce and the original shared secret.
3. The authentication server looks at the HMAC-signed version of the nonce it recently sent and confirms that the mobile device was able to encrypt it with the shared secret key. This tells the server that the mobile device is who it claims to be, so the server authenticates the device. **The server can then derive the same symmetric shared session key using its own nonce, the received nonce, the initial shared secret key, the mobile device's MAC address, and the AS's MAC address.**

The derived symmetric shared session key is then shared with the AP, so the mobile device and the AP can exchange data with each other.

### 802.11 Security Messaging Protocols

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/218797046-55dc787e-6cf4-41da-96f7-9dda1e363ee0.png" alt="Protocols"></p>


The figure above shows the `Extensible Authentication Protocol (EAP)` used to implement the 802.11 security framework.

This protocol defines the end-to-end message formats.

EAP messages are encapsulated using EAPoL and sent over the wireless link.

These EAP messages are decapsulated at the AP, re-encapsulated using the RADIUS protocol, and sent to the authentication server over UDP/IP.

## 8.8.2 Authentication and Key Agreement in 4G/5G Cellular Networks

The goals of mutual authentication and key generation in 4G/5G environments are the same as in 802.11 environments.

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/218796233-05da2b86-db94-4546-8507-1489d7379783.png" alt="4G"></p>


The 4G authentication and key agreement protocol:

1. Authentication request to the HSS
    - When a mobile device first requests to attach to the network via a base station, it sends an attach message containing its International Mobile Subscriber Identity (IMSI), which is relayed to the Mobility Management Entity (MME).
    - The MME sends the IMSI and information about the visited network to the HSS.
2. Authentication response from the HSS
    - The HSS uses the pre-shared secret key to perform cryptographic operations that derive an authentication token, auth_token, and an expected authentication response, xres.
    - auth_token contains information encrypted by the HSS with the pre-shared secret key, which lets the mobile device know that whoever computed auth_token knows the secret key.
    - In other words, auth_token is K(IMSI) under the pre-shared key. Anyone holding the same pre-shared key can recover the IMSI, so the mobile device learns that the HSS knows the secret key and authenticates the HSS as a legitimate network.
    - xres contains the value the mobile device is expected to compute; it lets the MME confirm that the mobile device knows the secret key, so the MME can authenticate the device.
    - The MME acts only as a middleman: it receives the authentication response message, stores xres for later use, extracts the authentication token, and forwards it to the mobile device.
3. Authentication response from the mobile device
    - The mobile device decrypts auth_token with the pre-shared key to obtain the IMSI, authenticating the HSS.
    - The mobile device computes a value res using its own secret key and sends it to the MME.
4. Mobile device authentication
    - The MME compares res, computed by the mobile device, with xres, computed by the HSS. If they match, both have proven they hold the common secret key, so the MME authenticates the mobile device.
    - The MME informs the base station and the mobile device that mutual authentication is complete, and sends the base station key to be used in the next step.
5. Data plane and control plane key derivation
    - The mobile device and the base station each determine the encryption/decryption keys to be used for sending frames over the wireless channel.
