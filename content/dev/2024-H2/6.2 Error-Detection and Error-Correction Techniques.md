# 6.2 Error-Detection and Error-Correction Techniques

<p align="center"><img width="400" alt="Error detection" src="https://user-images.githubusercontent.com/76640167/214039458-a74c70d2-02cf-4826-aa1c-af15edab8b58.png">

To guard against bit errors, the sending node augments the `data D` with `error-detection and -correction bits (EDC)`.

<br/>

Both the transmitted `data D` and the `EDC` can be altered in transit.

So the receiver has to check for errors using bits that may themselves have been altered.

<br/>

Even with error-detection and -correction techniques, there can still be undetected bit errors.

That is, the receiver might pass a corrupted datagram up to the network layer, or be unaware that the contents of some other field in the frame header are wrong.

So we want to choose a scheme that keeps the probability of missing an error low. (In general, the lower that probability, the larger the overhead.)

<br/>


## 6.2.1 Parity Checks

### Single parity bit

<p align="center"><img width="250" alt="Parity bit" src="https://user-images.githubusercontent.com/76640167/214039452-91447fa5-b3b5-42e3-bafd-10cce4bc00e4.png">

Suppose the data D has d bits.

In an even parity scheme, the sender simply appends one `parity bit` to D and chooses its value so that the total number of 1s in the d+1 bits is even.

The receiver checks that the number of 1s in the received d+1 bits is even.

(For an odd parity scheme, of course, the number of 1s is made odd instead.)

<br/>


With this method, an odd number of bit errors can be detected, but an even number of bit errors cannot.

Measurements have shown that errors are often clustered together in bursts, so with this method the probability of detecting an error can be as low as 50%.

<br/>

### Two-dimensional parity

<p align="center"><img width="350" alt="Two-dimensional parity bits" src="https://user-images.githubusercontent.com/76640167/214039449-ce67b6cd-f4ea-4042-b93b-bc57003f4e37.png">

The d bits in D are divided into i rows and j columns.

A parity value is computed for each row and each column.

<br/>


In the two-dimensional parity scheme, the parity of both the column and the row containing the flipped bit will be in error.

So the receiver can not only **detect that a single-bit error has occurred but also correct it, using the column and row indices**.

Also, unlike single parity, it can detect any combination of two errors. (It can't correct them, though.)

<br/>

### Forward error correction (FEC)

The receiver's ability to both detect and correct errors is known as `FEC`.

`FEC` techniques can reduce the number of retransmissions the sender is asked to make.

They also remove the need to wait a round-trip delay for the sender to receive a NAK packet and for the retransmitted packet to reach the receiver.

<br/>

## 6.2.2 Checksumming Methods

The d bits of data are treated as a sequence of k-bit integers, these k-bit integers are summed, and the resulting sum is used as the error-detection bits.

<br/>

### How the checksum works

`Internet checksum`

1. The 1s complement of the sum is the Internet checksum, which is placed in the segment header.
2. The receiver computes the sum of the received data and the checksum.
3. It checks the checksum by verifying that the result consists entirely of 1 bits.

<br/>

Checksumming has relatively low packet overhead, so it's used in `TCP` and `UDP`. However, compared with a `cyclic redundancy check (CRC)`, it offers relatively weak protection against errors.

`TCP` and `UDP` use this approach because both protocols are implemented in software, so they need a simple and fast error-detection scheme. The link layer, on the other hand, is implemented in hardware in the network adapter, so it uses a `cyclic redundancy check (CRC)`.

<br/>

## 6.2.3 Cyclic Redundancy Check (CRC)

*An error-detection technique widely used in today's computer networks is based on `cyclic redundancy check (CRC) codes`.*

CRC codes are also known as `polynomial codes`, since the bit string can be viewed as a polynomial whose coefficients are the 0 and 1 values in the bit string, and operations on the bit string can be interpreted as polynomial arithmetic.

<br/>


### How CRC works

<p align="center"><img width="400" alt="CRC" src="https://user-images.githubusercontent.com/76640167/214039446-5b9287a6-90fc-4040-8db6-81958b4f42cc.png">

1. First, the sender and receiver agree on an r+1 bit pattern G, known as the generator. The most significant (leftmost) bit of G must be 1.
2. The sender chooses r additional bits, R, and appends them to D.
    - In ordinary binary arithmetic, multiplying by 2^r is the same as shifting the bit pattern r bits to the left. So the formula in the figure above produces the d+r bit pattern.
    - The resulting d+r bit pattern is exactly divisible by G using modulo-2 arithmetic.
3. The receiver divides the d+r received bits by G. If the remainder is nonzero, an error has occurred.

<br/>

All CRC calculations use modulo-2 arithmetic, with no carries in addition and no borrows in subtraction.

That is, **this is the same as a bitwise XOR of the operands.**

e.g.

```
1011 XOR 0101 = 1110
1001 XOR 1101 = 0100

1011 - 0101 = 1110
1001 - 1101 = 0100
```

<br/>

### Computing R

First, we need to find an R such that there exists an n satisfying:

```
D x 2^r XOR R = nG
```

<br/>


That is, we want to choose R so that G divides `D x 2^r XOR R` with no remainder. If we XOR (that is, add modulo 2, without carry) R to both sides of this equation, we get:

```
D x 2^r = nG XOR R
```

<br/>

This equation tells us that if we divide `D x 2^r` by G, the remainder is exactly R.

In other words, R can be computed as follows:

```
R = remainder of (D x 2^r) / G
```

<br/>


e.g.

<p align="center"><img width="300" alt="CRC e.g." src="https://user-images.githubusercontent.com/76640167/214039442-8d067a82-0303-49d3-9dd6-697e560578dc.png">

<br/>
<br/>

International standards define 8-, 12-, 16-, and 32-bit generators G.

Each CRC standard can detect any burst error of r or fewer consecutive bits.
