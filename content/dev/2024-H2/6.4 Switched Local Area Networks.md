# 6.4 Switched Local Area Networks

<p align="center"><img width="600" alt="Switched local area network" src="https://user-images.githubusercontent.com/76640167/214864184-93f04822-630e-4fb7-82e4-1453028bf915.png">

Because switches operate at the link layer, they switch link-layer frames.

They also don't recognize network-layer addresses, and they don't use routing algorithms like OSPF to determine paths through a network of layer-2 switches.

In other words, they **use link-layer addresses** rather than IP addresses.

<br/>

## 6.4.1 Link-Layer Addressing and ARP

### Network-Layer Addresses vs. Link-Layer Addresses

Why have link-layer addresses when we already have network-layer addressing?

1. LANs were designed for arbitrary network-layer protocols, not just for IP and the Internet.
2. If adapters used network-layer addresses instead of MAC addresses, the network-layer address would have to be stored in the adapter's RAM and reconfigured every time the adapter moved.

In short, for the layers to be independent building blocks in a network architecture, each layer needs its own addressing scheme.

<br/>

### MAC Addresses

<p align="center"><img width="400" alt="MAC addresses" src="https://user-images.githubusercontent.com/76640167/214864181-000d5599-c0e3-451f-98ad-266d5e54debd.png">

Strictly speaking, it's not hosts or routers that have link-layer addresses, but their adapters (network interfaces).

So a host or router with multiple network interfaces has multiple link-layer addresses.

<br/>

However, since a link-layer switch's job is just to carry datagrams between hosts and routers, the switch's interfaces that connect to hosts and routers aren't assigned link-layer addresses.

<br/>
<br/>

**MAC address notation**

A MAC address is a link-layer address. For most LANs it's 6 bytes long, which gives 2^48 possible LAN addresses.

As shown in the figure above, each byte is usually written as two hexadecimal digits.

<br/>

MAC addresses were originally designed to be permanent, but nowadays you can change an adapter's MAC address in software.

<br/>

The IEEE manages the MAC address space to make sure every adapter has a different address.

A company that wants to manufacture adapters buys a block of 2^24 addresses, which fixes the first 24 bits; the company then assigns the remaining 24 bits uniquely to each adapter, giving it 2^24 addresses to hand out.

<br/>

MAC addresses have a flat structure rather than a hierarchical one, and they don't change when the device moves.

If an IP address works like a postal address, a MAC address works like a social security number.

<br/>
<br/>

**How adapters send and receive using MAC addresses**

1. The sending adapter puts the destination adapter's MAC address in the frame and sends it onto the LAN.
    - A switch often broadcasts a frame out of all its interfaces.
    - So an adapter may receive frames that aren't addressed to it.
2. The adapter that receives the frame checks whether the destination MAC address in the frame matches its own MAC address.
3. If it matches, it extracts the datagram and passes it up the protocol stack.
4. If it doesn't match, it discards the frame.

<br/>

When a sender wants every other adapter on the LAN to receive and process the frame, it uses the `MAC broadcast address`.

This is a 6-byte address with all bits set to 1.


### ARP

<p align="center"><img width="400" alt="ARP" src="https://user-images.githubusercontent.com/76640167/214864178-a1d7eb1b-8a60-47a3-8784-dc2fd974ed64.png">

Since there are both network-layer addresses and link-layer addresses, we need a protocol to translate between them: the `ARP (Address Resolution Protocol)`.

Like IP and MAC addresses, an `ARP module` exists on each interface.

<br/>

In the figure above, suppose A wants to send a datagram to C.

To send the datagram, A has to provide not only the destination IP address but also the MAC address, so that the LAN can deliver it properly to C.

<br/>

The sending host, A, needs to know the MAC address of the host with the destination IP address, and that's what ARP does.

Given any IP address on the same LAN as input, the sending host's ARP module returns the corresponding MAC address.

<br/>

In this respect it's similar to DNS.

However, while DNS resolves hostnames for hosts anywhere on the Internet, **ARP only resolves IP addresses of host and router interfaces on the same subnet**.

<br/>
<br/>

**How ARP works**

Each host and router keeps an `ARP table` in its memory.

This table holds mappings between IP addresses and MAC addresses, along with a `TTL (time-to-live)` value indicating when each mapping will be deleted from the table.

<br/>

Typically, an entry is deleted 20 minutes after it's added to the table.

<br/>

The table doesn't need entries for every host and router on the subnet.

So when a node wants to send a datagram, its ARP table may not have an entry for the destination node.

<br/>

Here's how that case is handled.

1. To resolve the MAC address, the sending node uses the ARP protocol and passes a special packet called an `ARP packet` to its adapter.
    - An ARP packet has fields for the sending and receiving IP and MAC addresses, and query and response packets share the same format.
    - The purpose of the query packet is to ask all the other hosts and routers on the subnet for the MAC address corresponding to the IP address being resolved.
    - The query packet is sent in a broadcast frame.
2. The adapter encapsulates the ARP packet in a link-layer frame and sends it with the MAC broadcast address (FF-FF-FF-FF-FF-FF) as the destination.
3. The query is received by every other adapter on the subnet, and because of the broadcast address, each adapter passes the ARP packet in the frame up to its ARP module.
4. Each ARP module checks whether its IP address matches the destination IP address in the ARP packet.
5. The node with the matching address sends back a response packet containing the requested mapping.
    - The query packet is sent in a broadcast frame, while the response packet is sent in a standard frame.
6. The querying host updates its ARP table.

<br/>

So a node's `ARP table` is `plug-and-play`: it's built automatically without an administrator having to configure it.

Because ARP deals with both link-layer addresses and network-layer addresses, it's a protocol that sits on the boundary between the network layer and the link layer.

<br/>

### Sending a Datagram to a Node Outside the Subnet

<p align="center"><img width="750" alt="Sending a datagram to a node outside the subnet" src="https://user-images.githubusercontent.com/76640167/214864175-d885eaa2-fff3-4b6b-8d02-1ccb4e6a109a.png">

In the figure above, suppose host `111.111.111.111` wants to send an IP datagram to host `222.222.222.222`.

The router has two IP addresses, two ARP modules, and two adapters (each adapter has its own MAC address, so there are two MAC addresses as well).

The sending host has to pass its adapter a datagram along with the appropriate destination MAC address and IP address.

<br/>

If the sending adapter used `49-BD-D2-C7-56-2A` as the destination MAC address, that address wouldn't match the MAC address of any adapter on the subnet containing host `111.111.111.111`, so no adapter on the subnet would pass the IP datagram up to its network layer.

In other words, the datagram would never be delivered and would just vanish.

<br/>

For the datagram to get through, it has to be sent to the router interface `111.111.111.110`. So the correct MAC address for this frame is the router interface's `E6-E9-00-17-BB-4B`.

<br/>

**How it works**

1. The sending host learns the MAC address of `111.111.111.110` using ARP.
2. Once it knows the MAC address, the sending host **sends the datagram, with destination IP address `222.222.222.222`, onto the subnet along with the MAC address it just learned**. The router's adapter on that subnet sees a matching MAC address and passes it up to the network layer.
3. The router's forwarding table tells the router to forward the datagram via router interface `222.222.222.220`.
4. The interface passes the datagram to its adapter, which encapsulates the datagram in a new frame and sends that frame onto the other subnet.
    - Naturally, the destination MAC address here is also obtained through ARP.

<br/>

## 6.4.2 Ethernet

Today, Ethernet is by far the dominant LAN technology.

If the Internet is about global networking, Ethernet is about local networking.

<br/>

**How it evolved**

- 1980s
    - Ethernet LANs used a coaxial bus to connect nodes.
    - Bus-topology Ethernet is a broadcast LAN: every transmitted frame travels past, and is processed by, every adapter connected to the bus.
- 1990s
    - LANs were replaced by Ethernet using a hub-based star topology.
    - Hosts connect directly to the hub with twisted-pair copper wire.
    - A `hub` is a physical-layer device that acts on individual bits rather than frames.
    - When a `hub` receives a bit on one interface, it sends a copy of that bit out of all its other interfaces.
- Early 2000s
    - The central hub was replaced by a `switch`.
    - A `switch` is not only collision-free but also a store-and-forward packet switch.

<br/>

### Ethernet Frame Structure

<p align="center"><img width="800" alt="Ethernet frame" src="https://user-images.githubusercontent.com/76640167/214864172-56d0a3f3-1ea3-41a1-b1ae-1033039847eb.png">

- Data field (46-1,500 bytes)
    - This field carries the IP datagram.
    - If a datagram exceeds 1,500 bytes, the host has to fragment it.
    - If it's smaller than 46 bytes, the data field has to be padded out to 46 bytes. The length field in the IP datagram header is used to strip the padding.
- Destination address (6 bytes)
    - Holds the destination MAC address.
- Source address (6 bytes)
    - Holds the source MAC address.
- Type field (2 bytes)
    - Allows Ethernet to multiplex network-layer protocols.
    - In other words, it allows network-layer protocols other than IP to be used.
- Cyclic redundancy check (CRC) (4 bytes)
    - The purpose of the CRC field is to let the receiving adapter detect whether errors have been introduced into the frame.
- Preamble (8 bytes)
    - An Ethernet frame begins with an 8-byte preamble field.
    - The first 7 bytes of the preamble have the value `10101010`, and the last byte is `10101011`.
    - The first 7 bytes wake up the receiving adapter and synchronize the receiver's clock with the sender's clock.
    - The sending adapter tries to transmit at the target rate for its type of Ethernet LAN, but it can't hit the rate exactly, so the receiving adapter syncs to the sender's clock simply by locking onto the bits in the first 7 bytes of the preamble.
    - The last two bits of the 8th byte tell the receiving adapter that the important stuff is about to arrive.

<br/>

### Ethernet as a Connectionless, Unreliable Service

When the sending adapter transmits a datagram, it encapsulates it in an Ethernet frame and sends it onto the LAN without any handshaking.

The receiving adapter checks the frame with the CRC, but it doesn't send an acknowledgment or a negative acknowledgment.

If the check fails, it just discards the frame.

Whether the loss of a datagram is ever noticed depends on whether the application uses UDP or TCP.

With UDP it isn't; with TCP, the loss is detected and the data is retransmitted.

And Ethernet itself can't tell whether the datagram it's transmitting is a retransmission or a new one.

<br/>

### Ethernet Technologies

<p align="center"><img width="700" alt="Ethernet technologies" src="https://user-images.githubusercontent.com/76640167/214864165-8bc1b17f-997a-4d55-8f1d-4b0280098251.png">

Ethernet has evolved over the years, and today's Ethernet is quite different from the original bus-topology design that used coaxial cable.

These days, nodes connect to a switch over point-to-point segments made of twisted-pair copper or fiber-optic cable.

Even as Ethernet has evolved, the frame format has stayed the same.

The Ethernet standards for bus topologies and hub-based star topologies were broadcast links, where frames collide if nodes transmit at the same time.

To deal with these collisions, they included the CSMA/CD protocol.

<br/>

The Ethernet most commonly used today is a switch-based star topology doing `store-and-forward packet switching`. Does it still need a MAC protocol?

A switch-based Ethernet LAN has no collisions, so it doesn't need a MAC protocol.

<br/>

## 6.4.3 Link-Layer Switches

A switch's job is to receive incoming link-layer frames and forward them onto outgoing links.

The switch itself is transparent to the hosts and routers on the subnet.

That is, a host or router addresses a frame to another host or router (not to the switch) and sends it onto the LAN, unaware that a switch in the middle is receiving the frame and forwarding it to other nodes.

The rate at which frames arrive at one of the switch's output interfaces can temporarily exceed that interface's link capacity.

To handle this, switch output interfaces have buffers.

<br/>

### Forwarding and Filtering

- `Filtering`
    - The switch function that decides whether a frame should be forwarded to some interface or dropped
    - Uses the `switch table`
- `Forwarding`
    - The function that determines which interface a frame should go out on and moves the frame to that interface
    - Uses the `switch table`
- `Switch table`
    - Contains entries for some, but not necessarily all, of the hosts and routers on the LAN.
    - A switch table entry contains:
        - A MAC address
        - The switch interface that leads toward that MAC address
        - The time the entry was created

<br/>

**How switch table entries are used**

Suppose a frame with some destination address arrives at switch interface x.

- **No entry for the destination address** in the table
    - The switch forwards a copy of the frame to the output buffers of every interface except the one it arrived on.
    - In other words, it broadcasts the frame.
- The table has an entry associating the destination address with **interface x**
    - The frame came from the LAN segment that contains the destination adapter.
    - There's no need to forward it to any other interface, so the switch performs filtering by discarding the frame.
- The table has an entry associating the destination address with interface y≠x
    - The frame needs to be forwarded to the LAN segment attached to interface y.
    - The switch performs forwarding by putting the frame in that interface's output buffer.

<br/>

### Self-Learning

Switches have the property that their tables are built automatically, dynamically, and autonomously: they're `self-learning`.

**How it works**

1. The switch table starts out empty.
2. For each frame received on an interface, the switch stores:
    - The MAC address in the frame's source address field
        - So the next time a frame from another LAN segment has that MAC address in its destination field, the switch can forward it correctly.
    - The interface the frame arrived on
    - The current time
3. Once every host on the LAN has sent a frame, the table ends up with information about every host.
4. If the switch hasn't received a frame with a given address as its source address after the `aging time` has passed, it deletes that address from the table.
    - So if a PC is replaced by a different PC, the old PC's MAC address is eventually removed from the switch table.

Since switches need no intervention from a network administrator or user, they're `plug-and-play devices`.

<br/>

### Properties of Link-Layer Switching

- Elimination of collisions
    - A LAN built from switches wastes no bandwidth on collisions.
    - The switch buffers frames and never transmits more than one frame on a segment at any one time.
    - This gives much better performance than a LAN with broadcast links.
- Heterogeneous links
    - Because a switch isolates links from one another, each link in the LAN can run at a different speed and over a different medium.
- Management
    - Besides offering better security, switches make network management easier.
    - e.g. If a cable gets cut, only the host on that cable loses its connection. If a malfunctioning adapter keeps sending frames, the switch can detect the problem and deliberately disconnect it.
    - Switches can also collect statistics on bandwidth usage, collision rates, and traffic types.

<br/>

### Focus on Security

- When the switch table has an entry
    - A host connected to a switch normally only receives frames addressed to it, so other hosts can't snoop on its frames.
- When the switch table has no entry
    - Because the switch broadcasts the frame, a sniffer can snoop on some frames that aren't addressed to it.
    - Attackers exploit this with a technique called `switch poisoning` to snoop on frames.
        - `Switch poisoning` means sending a large number of packets with many bogus source MAC addresses, filling the switch table with fake entries and leaving no room for the MAC addresses of legitimate hosts.

<br/>

### Switches vs. Routers

<p align="center"><img width="750" alt="Switches vs. routers" src="https://user-images.githubusercontent.com/76640167/214864160-537f30f6-bca5-4b5a-a30f-f00fab1c9b5a.png">

- Router
    - A store-and-forward packet switch that forwards packets using network-layer addresses.
    - A layer-3 packet switch.
- Switch
    - Also a store-and-forward packet switch, but it forwards packets using MAC addresses.
    - A layer-2 packet switch.

Although the two are fundamentally different (one uses MAC addresses, the other IP addresses), network administrators often have to choose between them when installing an interconnection device.

In fact, a router can also let departments communicate with each other without collisions.

<br/>

**Pros of switches**

- They're `plug-and-play devices`, so administrators don't have to worry much about them.
- They have high packet filtering and forwarding rates.

<br/>

**Cons of switches**

- To prevent broadcast frames from cycling, the active topology of a switched network is restricted to a spanning tree.
- In a large switched network, hosts and routers end up with large ARP tables, and a significant amount of ARP traffic is generated and processed.
- They offer no protection against broadcast storms.

<br/>

**Pros of routers**

- Because addressing is hierarchical, packets don't cycle through routers even when the network has redundant paths. So they're not restricted to a spanning tree and can use the best path.
- Without that restriction, the Internet topology can be built freely.
- They provide firewall protection against broadcast storms.

<br/>

**Cons of routers**

- They're not `plug-and-play devices`.
- They have a larger per-packet processing time than switches.

Generally, for a small network, switches are enough: traffic stays local, and they increase aggregate throughput without requiring any IP address configuration.

But large networks, typically made up of thousands of hosts, include routers as well.

<br/>

## 6.4.4 Virtual Local Area Networks (VLANs)

<p align="center"><img width="700" alt="Virtual local area network" src="https://user-images.githubusercontent.com/76640167/214864157-78d63e54-0306-4023-b37b-d6e98fa3babf.png">

In the setup above, the switches are arranged hierarchically. This configuration has the following drawbacks.

- Lack of traffic isolation
    - The hierarchy keeps each group's traffic within a single switch, but broadcast traffic still has to traverse the entire network.
    - Limiting the scope of broadcasts would improve LAN performance.
- Inefficient use of switches
    - If the organization had 10 groups instead of 3, it would need 10 first-level switches.
    - If each group had fewer than 10 people, a single 96-port switch could accommodate everyone, but a single switch can't provide traffic isolation.
- Managing users
    - When an employee moves from one group to another, the physical cabling has to be changed to connect that employee to a different switch.

These drawbacks can be solved with switches that support `virtual local area networks (VLANs)`.

<br/>

A switch that supports VLANs lets you define multiple virtual local area networks on top of a single physical LAN infrastructure.

Hosts within a VLAN communicate with each other as if they (and no other hosts) were the only ones connected to the switch.

In a port-based VLAN, the network administrator divides the switch's ports (interfaces) into groups.

Each group makes up a VLAN, and the ports in a VLAN form a single broadcast domain.

In other words, broadcast traffic from a port can only reach other ports in the same group.

<br/>

### Basic VLAN

<p align="center"><img width="700" alt="VLAN" src="https://user-images.githubusercontent.com/76640167/214864149-ba81a944-ce7b-4f0b-9942-21bbae0fe277.png">

The figure above shows a single switch with 16 ports.

Ports `2-8` belong to the EE VLAN, and ports `9-15` belong to the CS VLAN.

- The VLANs isolate each group's frames from one another.
- To move someone to another group, the administrator just reconfigures which group the port belongs to.
- The two switches that used to serve the two groups are replaced by a single switch.

So it solves all of the drawbacks above.

<br/>

A VLAN switch maintains a port-to-VLAN mapping table, which the network administrator can change using the switch's management software.

The switch hardware only forwards frames between ports that belong to the same VLAN.

<br/>

### **Sending Traffic from the EE VLAN to the CS VLAN**

The EE VLAN and CS VLAN are physically on the same switch but logically separate LANs, so traffic between them has to go through another switch or a router.

- Connect a VLAN switch port (an unused one, e.g. port 1 in the figure above) to an external router.
- Configure that VLAN switch port to belong to both LANs.
- A datagram first passes through the EE VLAN and reaches the router.
- The router then forwards it over the CS VLAN to the CS host.

Switch vendors make this easier for network administrators by building both a VLAN switch and a router into a single device.

<br/>

### **When an External Switch Needs to Join the VLANs**

<p align="center"><img width="700" alt="VLAN with an external switch" src="https://user-images.githubusercontent.com/76640167/214864142-d61da77a-1d2e-4769-b60c-513ec4e23c86.png">

If a switch has N VLANs, you can assign N ports to the N VLANs and connect each one to the external switch, letting the external switch work together with the VLAN switch.

But N VLANs need N ports, so this doesn't scale well.

<br/>

<p align="center"><img width="700" alt="VLAN trunking" src="https://user-images.githubusercontent.com/76640167/214864132-da03841d-5eed-4dd0-a262-43be473ea3e1.png">

The approach shown above is `VLAN trunking`.

On each switch, one special port is configured as a `trunk port` that interconnects the two switches' VLANs.

A `trunk port` belongs to all VLANs, and frames sent on any VLAN are forwarded over the trunk link to the other switch.

But then how does a switch know which VLAN a frame arriving on a trunk port belongs to?

To solve this, the IEEE defined an extended Ethernet frame format for frames crossing a VLAN trunk.

The extended Ethernet frame format carries a 4-byte `VLAN tag` in its header that identifies the VLAN.

The `VLAN tag` is added by the sending switch, and parsed and removed by the receiving switch.

<br/>

<p align="center"><img width="700" alt="VLAN tag" src="https://user-images.githubusercontent.com/76640167/214872229-68994ade-4e37-4c1c-9f9c-84195afe7de8.png">

Structure of a `VLAN tag`

- 2-byte Tag Protocol Identifier (TPID) field
- 2-byte Tag Control Information field
  - 12-bit VLAN identifier field
  - 3-bit priority field
