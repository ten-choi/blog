# 7.4 Cellular Networks: 4G and 5G

<br/>

### Cellular Networks

- The term `cellular` comes from the fact that the area covered by a cellular network is **divided into a number of geographic areas called** `cells`, based on radio coverage.
- Each cell contains a `base station` that sends signals to and receives signals from the `mobile devices` within the cell.
- The size of the area a cell covers depends on several factors:
    - The transmit power of the base station and the devices
    - Obstructing buildings within the cell
    - The height and type of the base station antennas

<br/>
<br/>

### Mobile Device

> A smartphone, tablet, laptop, or IoT device (including fixed temperature sensors or surveillance cameras) connected to a cellular carrier's network,  
> where web browsers, map apps, voice and video conferencing apps, mobile payment apps, and so on run.

- Also called `UE (User Equipment)`
- Implements the full `5-layer Internet protocol stack`.
- It is a **network endpoint** with an `IP address`, which is typically obtained via NAT.
- It has a globally unique 64-bit identifier called the `IMSI (International Mobile Subscriber Identity)`.
    - It identifies the subscriber across the world's cellular carrier systems, including the subscriber's country and home network. (Similar to a MAC address)
    - It is stored on the `SIM (Subscriber Identity Module) card`.
        - The SIM card stores, in encrypted form, information about the services the subscriber can access and the subscriber's key information.

<br/>

### Base Station

> Sits at the edge of the cellular carrier's network and is **responsible for managing the radio resources and the mobile devices** within its coverage area.

- Mobile devices attach to the carrier's network by interacting with a base station.
- Coordinates device authentication and the allocation of resources (radio channels) in the radio access network.
- Unlike an AP in a wireless LAN, a cellular base station also performs the following roles:
    - Creates `device-specific IP tunnels` from the mobile device to the gateways, and interacts with other base stations to handle device mobility between cells.
    - Neighboring base stations coordinate with each other to manage the radio spectrum and minimize interference between cells.

<br/>

### Home Subscriber Server (HSS)

> A database that stores information about the mobile devices for which the HSS's network is the home network

- A control-plane element
- Used together with the `Mobility Management Entity (MME)` to authenticate mobile devices.

<br/>

### S-GW (Serving Gateway) and P-GW (Packet Data Network Gateway)

The `S-GW` and the `PDN Gateway (P-GW)` are two routers that sit between the mobile device and the Internet.

<br/>

#### PDN Gateway (P-GW)

- Provides `NAT IP addresses` to mobile devices and performs the `NAT function`.
- To the outside world, the P-GW looks just like any other gateway router.
- The mobility of mobile nodes within the carrier's LTE network is hidden from the outside world behind the P-GW.

Besides these gateway routers, the carrier's `all-IP core` also contains routers that perform traditional routing functions.

<br/>

### Mobility Management Entity (MME)

- A control-plane element
- Plays a key role, together with the HSS, in **authenticating** devices that want to connect to the network.
- Sets up the tunnels on the data path between mobile devices and the PDN Internet gateway, and maintains cell location information for active mobile devices within the carrier's cellular network.  
  However, it is not on the forwarding path of datagrams traveling to or from the Internet. (You can see this in the figure below.)

<br/>

### Authentication

- **Mutual** authentication between the network and the mobile device attached to it
    - The network needs to know that the attached device really is the device associated with the given IMSI.
    - The mobile device needs to know that the network it is attaching to is a legitimate cellular carrier network.
- The `MME` acts as the intermediary between the mobile device and the `Home Subscriber Server (HSS)` in its home network.
    1. The local MME receives an attach request from the mobile device and contacts the HSS in the device's home network.
    2. The device's home HSS returns enough encrypted information to the local MME.

<br/>

### Path Setup

> **The data path from the mobile device to the gateway router** consists of  
> the wireless first hop between the mobile device and the base station, plus the concatenated `IP tunnels` between the base station and the `serving gateway (S-GW)` and between the serving gateway and the `PDN gateway`.

- The `tunnels` are set up under the control of the MME.
- **When a device moves to a different base station, only the tunnel endpoint terminating at the base station changes;** the other tunnel endpoints and the quality of service associated with the tunnel stay the same.

<br/>

### Cell Location Tracking

As a mobile device moves between cells, the base stations update the MME with the device's location.

However, if the mobile device is in sleep mode while moving between cells, the base stations can no longer track its location.

In that case, **it is the** `MME`**'s responsibility to locate the device** for wake-up, through a process called `paging`.

# 7.4.2 LTE Protocol Stacks

4G LTE has an `all-IP network architecture`.

So the upper layers of the LTE protocol stack consist of IP, TCP, UDP, and various application-layer protocols.

<br/>

The figure below shows the `user-plane protocol` stacks at the LTE mobile node, the base station, and the serving gateway.

As you can see, most of the user-plane protocol activity happens on the wireless link between the mobile device and the base station.

<br/>

<p align="center"><img width="810" alt="LTE data-plane protocol stacks" src="https://user-images.githubusercontent.com/86337233/216772902-3851b6a6-ca23-46e7-bd21-2384d14f11d3.png">

<br/>
<br/>
<br/>

LTE splits the mobile device's `link layer` into three sublayers.

<br/>

> 1️⃣ Packet Data Convergence

- `PDCP (Packet Data Convergence Protocol)` performs IP header compression to reduce the number of bits sent over the wireless link.
- It also performs encryption/decryption using keys established via signaling messages exchanged between the LTE mobile device and the Mobility Management Entity (MME)  
  when the device first attaches to the network.

<br/>

> 2️⃣ Radio Link Control (RLC)

- Performs **fragmentation** on the sending side and **reassembly** on the receiving side for `IP datagrams` too large to fit in link-layer frames.
- Provides **reliable data transfer** at the link layer using an `ACK/NAK-based ARQ protocol`.

<br/>

> 3️⃣ Medium Access Control (MAC)

- Performs **transmission scheduling**, i.e., requesting and controlling the use of radio transmission slots.
- The MAC sublayer also performs additional error detection/correction, including **forward error correction using redundant bits**.

<br/>
<br/>

The figure above also shows the use of `tunnels` on the user data path.

1. Tunnels are set up **under MME control** when the mobile device first attaches to the network.


2. Each tunnel between two endpoints has a unique `tunnel endpoint identifier (TEID)`.

   (1) When the base station receives a datagram from the mobile device, it encapsulates it using the `GPRS Tunneling Protocol`, including the TEID,  
   (2) and sends it in a UDP segment to the `serving gateway` at the other end of the tunnel.


3. (1) On the receiving side, the `base station` decapsulates the tunneled UDP datagram,  
   (2) extracts the IP datagram destined for the mobile device,  
   (3) and forwards that IP datagram to the mobile device over the wireless hop.

<br/>
<br/>

# 7.4.3 The LTE Radio Access Network

On the `downstream channel`, LTE uses **a combination of frequency-division multiplexing and time-division multiplexing**,  
known as `orthogonal frequency division multiplexing (OFDM)`.

<br/>

In LTE, each active mobile device is **allocated one or more 0.5 ms time slots on one or more channel frequencies.**

<br/>

The figure below shows eight time slots allocated across four frequencies.

- For each frequency, there are twenty 0.5 ms slots organized into a 10 ms frame
- Shaded: 8 of the 20 slots allocated

<br/>

<p align="center"><img width="500" alt="Orthogonal frequency division multiplexing" src="https://user-images.githubusercontent.com/86337233/216772903-ffda3be4-264b-4ad8-aae7-8330120e6608.png">

<br/>
<br/>

- **By being allocated more and more time slots**, whether on the same frequency or on different frequencies, **a mobile device can achieve increasingly higher transmission rates.**
- Slot (re)allocation among mobile devices can be done as often as once every millisecond.
- Transmission rates can also be changed by using different modulation schemes.

<br/>

`The allocation of specific time slots to mobile devices` is not mandated by the LTE standard;  
the decision of `which mobile devices are allowed to transmit in which time slot on which frequency` is made by scheduling algorithms provided by the LTE equipment vendor or the network operator.

# 7.4.4 Additional LTE Functions: Network Attachment and Power Management

### Network Attachment

The process by which a mobile device attaches to a cellular carrier's network has three phases.

<br/>

> 1️⃣ Attaching to a base station

1. The mobile device initially searches for the `primary synchronization signal`, which base stations broadcast every 5 ms on every channel in every frequency band.
2. Once it finds a primary synchronization signal, the device stays on that frequency and looks for the `secondary synchronization signal`.
    - Using the information in the secondary synchronization signal plus a few additional steps,  
      the device can find further information such as the channel bandwidth, channel configuration, and the base station's cellular carrier information.
3. Armed with this information, the mobile device selects a `base station` to attach to and can establish a control-plane signaling connection with it over the `wireless hop`.

<br/>

> 2️⃣ Mutual authentication

- The base station contacts the `MME (Mobility Management Entity)` to perform mutual authentication. (Covered in detail in Section 8.8.2.)
- Through mutual authentication, the network learns that the attaching device really is the **device associated with the given IMSI**,  
  and the mobile device learns that the network it is attaching to is a **legitimate cellular carrier network**.
- Once mutual authentication is complete, the MME and the mobile device have authenticated each other, and the MME also knows the `ID of the base station` the device is attached to.

<br/>

> 3️⃣ Setting up the path between the mobile device and the PDN gateway

- The `MME` contacts the PDN gateway (which also provides the NAT address for the mobile device), the serving gateway, and the base station to set up the *two tunnels* shown in the figure below.
- Once this step is complete, the mobile device can send and receive IP datagrams to and from the Internet through these tunnels via the base station.

<br/>

### Power Management: Sleep Modes

To minimize power consumption (= to minimize the time the device's circuitry must be powered on to send/receive data and sense the channel),  
wireless devices can enter a `sleep state` when they aren't transmitting or receiving.

<br/>

In 4G LTE, a sleeping mobile device can be in one of two sleep states:

- `Discontinuous reception state`
- `Idle state`

<br/>

#### Discontinuous Reception State

- "Light sleep"
- Typically entered after a few hundred milliseconds of inactivity.
- The mobile device and the base station schedule periodic wake-up times for the device in advance,  
  and at those times the device **actively monitors the channel** for downstream transmissions from the base station.
    - Apart from these scheduled times, however, the device's radio can be asleep.

<br/>

#### Idle State

- "Deep sleep"
- The sleep is so deep that if the mobile device moves to a new cell in the carrier's network while asleep, **it doesn't need to inform the base station it was previously associated with.**
- So when it wakes up from this deep sleep, the mobile device  
  must re-establish an association with a (potentially new) base station in order to check for `paging messages` that the MME broadcasts to base stations near the one the device was last associated with.
    - These `control-plane paging messages` are broadcast by the base stations to all mobile devices in their cells.
    - They indicate **which mobile device** must fully wake up and re-establish a new data-plane connection to a base station in order to receive packets.

How is the `global cellular network`, a "network of networks," organized?

- The user's home network connects to other cellular carriers' networks and to the global Internet through one or more `gateway routers` in the home network.


- The mobile networks themselves are interconnected via the public Internet or an `IPX (Internet Protocol Packet eXchange) network`.

# 7.4.6 5G Cellular Networks

> The ultimate `wide-area data service` would be one that is available everywhere: ubiquitous, with gigabit connection speeds, extremely low latency, and no limits on the number of users and devices.

<br/>

- `5G` is expected to deliver roughly 10x the peak bitrate, 10x lower latency, and over 100x the traffic capacity of 4G.


- Frequencies used
    - FR1 (450 MHz–6 GHz)
    - FR2 (24 GHz–52 GHz): `millimeter wave frequencies`
        - Pros: allow much faster data rates.
        - Cons
            - Much shorter reach from base station to receiver, which makes them unsuitable for rural areas and requires denser base station deployment in urban areas.
            - Highly susceptible to atmospheric interference.


- The `physical layer (i.e., radio)` side of 5G is **not backward compatible with 4G mobile systems** such as LTE.
    - Existing smartphones can't be supported through base station or software upgrades,  
      so carriers must invest heavily in physical infrastructure to transition to 5G.

<br/>
<br/>

## Standards

### eMBB (Enhanced Mobile Broadband)

- Provides increased bandwidth and moderate latency improvements. (For higher download and upload speeds compared to 4G LTE)

<br/>

### URLLC (Ultra Reliable Low-Latency Communications)

- Targets applications that are highly latency-sensitive. (e.g., factory automation and autonomous driving)
- Aims for 1 ms latency.

<br/>

### mMTC (Massive Machine Type Communications)

- A narrowband access type for sensing, metering, and monitoring applications.
- Focuses on reducing power requirements to lower the barrier to connecting IoT devices to the network.

<br/>
<br/>

## 5G and Millimeter Wave Frequencies

`Millimeter wave frequencies in the 24 GHz–52 GHz band` offer the potential for a 100x increase in data capacity over 4G.

<br/>

> `Data capacity`  
> = `cell density` (cells/km^2)  
> × `available spectrum` (Hz)  
> × `spectral efficiency` (how efficiently each base station can communicate with users, in bps/Hz/cell)

<br/>

- Millimeter wave frequencies have a much shorter range than 4G LTE frequencies, so more base stations are needed. → **Higher cell density**


- 5G FR2 operates over a much wider frequency band (52 − 24 = 24 GHz) than 4G LTE (up to about 2 GHz), so **more spectrum is available.**


- Doubling spectral efficiency would require a 17x increase in power, so 5G instead uses `MIMO technology` with multiple antennas at each base station.
    - Rather than broadcasting signals in all directions, each MIMO antenna uses beamforming to send signals directly to users.
    - This lets a base station transmit to 10–20 users simultaneously on the same frequency band.

<br/>

However, millimeter wave signals are easily blocked by buildings and trees,  
so `small cell stations` are needed to fill the coverage gaps between base stations and users.

<br/>
<br/>

## The 5G Core Network

> The data network that manages all 5G mobile voice, data, and Internet connectivity

- Redesigned to integrate better with the Internet and cloud-based services.
- Reduces latency by including distributed servers and caches throughout the network.
- The new 5G Core specifications introduce major changes in **how mobile networks support a wide variety of services with different performance requirements**:
    - Relaying data traffic from end devices
    - Authenticating devices
    - Managing device mobility
- It includes all of the network elements (mobile devices, cells, base stations, MME, HSS, serving gateways, PDN gateways).

<br/>

### 5G Core Architecture

The 5G Core is designed for **complete separation of the control plane and the user plane**, and it consists purely of virtualized, software-based network functions.

This gives carriers the flexibility to meet the diverse requirements of different 5G applications.

<br/>
<br/>

## Key 5G Core Network Functions

### User-Plane Function (UPF)

Separating the control and user planes allows packet processing to be pushed out and distributed to the network edge.

<br/>

### Access and Mobility Management Function (AMF)

The 5G Core essentially splits the 4G MME into two functional elements: the AMF and the SMF.

The AMF receives all connection and session information from end-user devices, but it only handles connection and mobility management tasks.

<br/>

### Session Management Function (SMF)

Session management is handled by the SMF.

It is responsible for interacting with the decoupled data plane, manages IP addresses, and acts as the `DHCP server`.
