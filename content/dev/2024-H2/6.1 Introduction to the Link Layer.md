# 6.1 Introduction to the Link Layer

<p align="center"><img width="400" alt="Link layer" src="https://user-images.githubusercontent.com/76640167/214023095-59309bd8-9f49-4618-a464-e040c1eb9952.png">

### Node

Any device that runs a link-layer protocol

e.g. hosts, routers, switches, APs (access points, covered in Chapter 7), etc.

<br/>

### Link

A communication channel connecting adjacent nodes along the communication path

To move a datagram from the source host to the destination host, the datagram has to be moved over each individual link along the end-to-end path.

Over a given link, the transmitting node encapsulates the datagram in a `link-layer frame` and transmits it onto the link.

<br/>

In the figure above, the datagram passes through six links.

<br/>

## 6.1.1 Services Provided by the Link Layer

- `Framing`
    - Before transmitting a datagram over a link, the link layer encapsulates it in a link-layer frame.
    - A frame consists of a data field, which holds the datagram, and a number of header fields.
- `Link access`
    - A `medium access control (MAC)` protocol specifies the rules for transmitting frames onto the link.
    - For a point-to-point link with a single sender and a single receiver, `MAC` is simple: the sender can transmit a frame whenever the link is idle.
    - When multiple nodes share a single broadcast link, the MAC protocol coordinates the frame transmissions of those nodes.
- `Reliable delivery`
    - Like `TCP`, it provides this service through acknowledgments and retransmissions.
    - Unlike `TCP`, which retransmits data end to end, a link-layer protocol corrects errors on the link where they occurred.
    - It's mainly used on links with high error rates, such as wireless links. On links with low bit error rates it can be unnecessary overhead, so most wired link-layer protocols don't provide it.
- `Error detection and correction`
    - Due to signal attenuation and electromagnetic noise, a transmitted frame bit can be misread as its opposite.
    - Since there's no point in forwarding a datagram that has an error, most link-layer protocols provide a way to detect errors.
    - This is done by having the transmitting node set error-detection bits and the receiving node perform an error check.
    - It's generally more sophisticated than error detection at the transport and network layers, and it's implemented in hardware.
    - Error correction is similar to error detection, but the receiver can also determine exactly where in the frame the error occurred.

<br/>

## 6.1.2 Where Is the Link Layer Implemented?

In a host, the link layer is for the most part implemented in a `network adapter`, also known as a `network interface controller (NIC)`.

(In a router, as we saw in Chapter 4, it's implemented on the line card.)

<p align="center"><img width="400" alt="Network adapter" src="https://user-images.githubusercontent.com/76640167/214023089-1ac99788-3cb3-461c-96df-e507f658a255.png">

<br/>

### Controller

Sits at the heart of the `network adapter`.

It's a special-purpose single chip that implements most of the link-layer services in hardware.

On the sending side, the controller takes a datagram stored in host memory, encapsulates it in a link-layer frame, and transmits the frame onto the communication link following the link-access protocol.

On the receiving side, the controller receives the frame and extracts the network-layer datagram.

<br/>

### CPU

Some link-layer functionality is implemented in software that runs on the host's `CPU`.

The higher-level link-layer functions are implemented in the link-layer software components.

e.g. assembling link-layer addressing information, activating the controller hardware, handling interrupts from the controller, error handling, passing datagrams up, etc.

<br/>

In other words, **the link layer is a combination of hardware and software**.
