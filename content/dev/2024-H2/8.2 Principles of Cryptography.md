# 8.2 Principles of Cryptography

The message in its original form, as sent by the sender, is called the **plaintext** or **cleartext**.

The sender encrypts the plaintext using an **encryption algorithm**, and the encrypted message, the ciphertext, can't be understood by an intruder.

The **encryption algorithm** itself is known to everyone and anyone can easily use it.

So we need some secret information that keeps an intruder from recovering the transmitted data — that's the **key**.

<br/>

### Scenario

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217251408-f146b7e8-fd9b-4b1e-afe8-ec5b32050d37.png" alt="Scenario"></p> 

1. Alice uses key A, a string of numbers or characters, as input to the encryption algorithm to produce the encrypted message `A(m)`.
2. Bob feeds key B and the ciphertext `A(m)` into the decryption algorithm and gets the output `B(A(m)) = m`.

<br/>

### Symmetric key systems

Alice's and Bob's keys are identical, and the key is a secret shared only by the two of them.

<br/>

### Public key systems

One of the keys is known to the whole world, and the other is known only to either Alice or Bob.

<br/>

## 8.2.1 Symmetric Key Cryptography

### Caesar cipher

For English plaintext, replace each letter with the letter k positions after it in the alphabet. (Wraparound is assumed: the letter 1 position after z is a.)

Here the value of k is the encryption key.

But if you know it's a Caesar cipher, you can decrypt the ciphertext in no time.

<br/>

### Monoalphabetic cipher

Instead of substituting by a fixed rule like the Caesar cipher, each letter is mapped to a unique substitute letter with no rule at all.

There are about 26! possible letter pairings, so it's more secure.

However, because letters like e and t appear frequently and certain 2–3 letter combinations tend to appear together, the cipher becomes easy to break.

For example, if you know the names of the people using the cipher appear in the plaintext, you can immediately pin down several letter pairs.

<br/>

**Scenarios depending on what the intruder knows**

- Ciphertext-only attack
    - The intruder has no information about the plaintext message.
- Known-plaintext attack
    - If the intruder knows in advance words (names, etc.) that will appear in the plaintext and ciphertext, they can learn the letter pairings for those words.
- Chosen-plaintext attack
    - The intruder can get the sender to send a plaintext message of the intruder's choosing and obtain the corresponding ciphertext.

<br/>

### Polyalphabetic encryption

Use several monoalphabetic ciphers, applying a different one depending on the position in the plaintext message.

In other words, the same letter is encrypted differently depending on where it appears in the plaintext.

<br/>

For example, call the first monoalphabetic cipher C1 and the second C2.

The first plaintext letter uses C1, the second C2, the third C1, and so on — the monoalphabetic cipher changes with the position in the plaintext.

<br/>

### Block ciphers

This is the encryption technique currently used in TLS, PGP, IPsec, and so on.

Widely used block ciphers today include AES, DES, and 3DES.

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217251406-3b72c7a2-2c5d-4b0e-b69e-9258b414b96c.png" alt="Block cipher example"></p> 

In a block cipher, the message is split into blocks of k bits, and each block is encrypted.

Each k-bit plaintext block is mapped one-to-one to a k-bit ciphertext block.

With the mapping in the table above, `010110001111` is encrypted to `101000111001`.

<br/>

For k bits there are `(2^k)!` possible mappings in total — an astronomically large number.

But with `k=64`, both sender and receiver would have to maintain a table of `2^64` inputs, which is practically infeasible, and a huge table would have to be regenerated every time the key changes, so this isn't usable in practice.

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217251401-4fedfa11-e63f-4c92-a439-3abe3167cea0.png" alt="Block cipher"></p> 

Instead, block ciphers use functions that simulate randomly permuted tables of input and output blocks.

The figure above shows an example with `k=64`.

**Scenario**
1. Split the 64-bit block into 8 chunks of 8 bits each.
2. Each 8-bit chunk is processed by a table that maps each 8-bit input block to an 8-bit output block — a manageable size.
3. Each chunk is processed by a table that maps each 8-bit input block to an 8-bit output block — a manageable size.
4. The encrypted chunks are reassembled into a single 64-bit block.
    - The positions are scrambled as they're reassembled.
5. Feed the 64-bit block back into the input.
6. Repeat this cycle n times.
    - This makes each input bit affect most of the final output bits.
    - With only one round, a single input bit would affect only 8 output bits.

If the scrambling rule is known, the key for this block cipher algorithm is the eight permutation tables.

<br/>

### Cipher block chaining

Network applications generally need to encrypt long messages, and using a block cipher here causes a subtle but important problem.

If two or more plaintext blocks are identical, they produce the same ciphertext, which gives an attacker a chance to guess the plaintext from the identical ciphertext.

Combine that with knowledge of the underlying protocols, and the entire message could be decrypted.

To fix this, we can add randomness so that the same plaintext block can produce different ciphertext blocks.

<br/>

**Scenario**

1. For the i-th plaintext block m(i), the sender generates a random k-bit number r(i).
2. It produces the ciphertext `K(r(i) xor m(i)) = c(i)`.
    - Because of r(i), the ciphertexts differ even if m(i) and m(j) are the same.
3. The receiver gets r(i) and c(i) and computes `m(i) = K(c(i)) xor r(i)`.
    - An intruder can see the unencrypted r(i), but without the key can't decrypt the plaintext m(i).

<br/>

However, the sender has to send twice as many bits and needs twice the bandwidth.

To solve this, the `Cipher Block Chaining (CBC)` technique is used.

<br/>

**Scenario**

1. Before encrypting the message, the sender generates a random k-bit string c(0) called the initialization vector.
2. The sender sends c(0) to the receiver.
3. For the first block, the sender computes `c(1)= K(m(1) xor c(0))`.
4. It sends the encrypted c(1) to the receiver.
5. From then on, the sender generates and sends ciphertext blocks as `c(i)= K(m(i) xor c(i-1))`.
    - Since the receiver knows c(i-1), it can keep decrypting.
    - Likewise, identical plaintext blocks produce different ciphertext.
    - An intruder can see the unencrypted c(0), but without the key can't decrypt the plaintext m(i).
    - The sender only has to send one extra initialization vector, so the bandwidth increase is negligible.

<br/>

## 8.2.2 Public Key Encryption

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217251395-2432f8e6-55be-4d61-9f6e-24e35c4e35ae.png" alt="Public key encryption"></p> 

In public key encryption, rather than the sender and receiver each having a key, the receiver has two keys.

One is the **public key**, known to the whole world, and the other is the **private key**, known only to the receiver.

<br/>

**Scenario**

1. To send a message to the receiver, the sender looks up the receiver's public key.
2. The sender encrypts the message with the receiver's public key and sends it.
3. The receiver decrypts the ciphertext using its private key and the decryption algorithm.

<br/>

### RSA

RSA makes heavy use of modulo-n arithmetic (remainders).

**Useful properties of modular arithmetic**

```
[(a mod n)+(b mod n)]mod n=(a+b)mod n
[(a mod n)−(b mod n)]mod n=(a−b)mod n
[(a mod n)⋅(b mod n)]mod n=(a⋅b)mod n

// Follows from the third property
(a mod n)^d mod n = a^d mod n
```

<br/>

**Choosing the public and private keys**

1. Choose two large prime numbers p and q.
    - The larger they are, the harder RSA is to break, but the longer encryption and decryption take.
2. Compute `n = pq` and `z = (p-1)(q-1)`.
3. Choose a number e (other than 1), less than n, that is relatively prime to z.
    - The e comes from encryption.
4. Find a number d such that ed-1 is exactly divisible by z.
    - The d comes from decryption.
    - In other words, choose d so that `ed mod z = 1`.
5. The public key is the pair (n, e), and the private key is (n, d).

How to pick large p and q, how to do the exponentiation, and how to pick e and d are beyond the scope of the book, so I'll skip them.

<br/>

**Algorithm scenario**

1. To encrypt, use the public key (n, e). Raise the message to the power e and take the remainder modulo n; that value is the ciphertext c.
    - The message is a k-bit string that corresponds to an integer, so it can be raised to the power e.
    - `c = m^e mod n`
2. To decrypt the received ciphertext c, use the private key (n, d).
    - Decrypt by computing `m = c^d mod n = m^ed mod n`.

<br/>

e.g.

The receiver chooses `p=5` and `q=7`.

Then `n = 35` and `z = 24`.

Since 5 and z have no common factors, choose `e = 5`.

Since `5×29-1` (i.e., ed-1) is divisible by 24, choose `d = 29`.

Now we have the public key (35, 5) and the private key (35, 29).

<br/>

Now let's encrypt and decrypt a plaintext m.

Assume m is the bit string 1100, which corresponds to the number 12.

Encryption: `m^e = 248832`, `17(c) = 248832(m^e) mod 35(n)`

Decryption: `12(m) = 481968572106750915091411825223071697(c^d) mod 35(n)`

<br/>

### Session keys

The exponentiation RSA requires is time-consuming, so in practice it's often used together with symmetric key encryption.

<br/>

**Scenario**

1. The sender picks a **session key** to use for encrypting data.
    - The session key is used for symmetric key encryption, which means the receiver needs to know it.
2. The sender RSA-encrypts the session key with the receiver's public key.
3. The receiver gets the ciphertext and decrypts it with its private key.
4. The receiver now has the session key and can decrypt the data the sender sends.

<br/>

### Why RSA works

We need to prove that `m = m mod n = m^ed mod n`.

From number theory, if p and q are prime, `n = pq`, and `z = (p-1)(q-1)`, then `x^y mod n` equals `x^(y mod z) mod n`.

So we get the following:

`m^ed mod n = m^(ed mod z) mod n`

Since we chose e and d so that `ed mod z = 1`, `m = m mod n = m^ed mod n`.

Since e and d are just exponents, swapping them works too.
