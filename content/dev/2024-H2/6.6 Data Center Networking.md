# 6.6 Data Center Networking

Besides being connected to the Internet, a data center has its own `data center network` that interconnects its internal hosts.

<br/>

The three purposes of a data center

1. Serving content such as web pages, search results, email, and streaming video
2. Acting as a massively parallel computing infrastructure for specific data-processing tasks, such as computing distributed indexes for search engines
3. Providing `cloud computing` to other companies

<br/>

## 6.6.1 Data Center Architecture

<p align="center"><img width="700" alt="Data center" src="https://user-images.githubusercontent.com/76640167/214875512-04558954-375e-44f4-89e1-71d25703126b.png">

<br/>

### Hosts

Hosts do the actual work in a data center.

They're also called `blades`, since they look like pizza boxes.

They're general-purpose hosts with CPUs, memory, and disk storage.

Hosts are stacked in `racks`, each of which can hold 20-40 blades.

Each host is assigned its own IP address that's used inside the data center.

<br/>

### TOR (Top of Rack) Switches

At the top of each rack sits a switch called the TOR switch.

The TOR switch connects the hosts in the rack via their network interface cards.

Its other ports connect it to the data center's other switches.

<br/>

### Border Routers

A data center has one or more border routers to handle traffic flowing between external clients and internal hosts.

Border routers connect the data center network to the public Internet.

<br/>

### Load Balancing

1. To support requests from external clients, each application is assigned a public IP address, and clients send requests to and receive responses from that address.
2. Requests are sent to a `load balancer`.
    - There are usually several `load balancers`, each dedicated to a particular cloud application.
    - A `load balancer` is also called a layer-4 switch, because it makes decisions based on the destination port as well as the destination IP address.
3. The `load balancer` distributes requests across hosts and balances the load among them based on their current load.
    - Because the `load balancer` translates the public external IP address into a host's internal IP address and back again, it provides NAT-like functionality.

By preventing clients from contacting hosts directly, it hides the internal structure and provides security.

<br/>

### Hierarchical Architecture

1. At the top of the hierarchy, the border routers connect to access routers.
2. The access routers connect to the top-tier switches.
    - Below the access routers there are three tiers of switches in total.
3. Each top-tier switch connects to multiple second-tier switches and a load balancer.
4. Each second-tier switch connects to multiple racks via the racks' TOR switches (the third tier).
5. The hosts connected to a rack form a single subnet.
    - To keep ARP broadcast traffic local, the subnet is further divided into smaller VLAN subnets.

Since keeping applications highly available matters a lot to cloud application providers, data center designs include redundant network equipment and links.

<br/>

### Problems with the Hierarchical Architecture

In the data center figure at the top, suppose 10 hosts in rack 1 each send a flow to a corresponding host in rack 5.

Likewise, suppose rack 2 sends flows to rack 6, rack 3 to rack 7, and rack 4 to rack 8.

If the flows crossing a link share its capacity fairly, the 40 flows crossing the link from A to B each get only `n Gbps/40`.

That becomes a problem whenever the network interface cards can transmit faster than `n Gbps/40`, and it gets much worse for host-to-host flows that have to cross the higher tiers.

<br/>

### Solutions

<p align="center"><img width="700" alt="Data center" src="https://user-images.githubusercontent.com/86337233/215983535-b093f961-b45d-41f1-b7c7-e19ee10767bf.png">

- Use higher-speed switches and routers.
    - This is expensive.
- Place related services and data as close together as possible, so that inter-rack communication through tier-2 or tier-1 switches is minimized.
    - This only goes so far, because a key requirement of data centers is flexibility in where computation and services are placed.
- Increase connectivity between TOR switches and tier-2 switches, and between tier-2 and tier-1 switches.
    - For example, connecting each TOR switch to two tier-2 switches provides multiple `link-disjoint` and switch-disjoint paths between racks.
    - Increasing the connectivity between tiers (path diversity) gives two benefits: more capacity between switches and better reliability.

<br/>

## 6.6.2 Trends in Data Center Networking

### Cost Reduction

The most important trend in data center networking is interconnecting data center hosts through tiered, layered networks.

That is, letting any host in the data center communicate with any other host.

These data center interconnection networks are built from many small switches.

<br/>

### Centralized SDN Control and Management

Because a data center is managed by a single organization, many large data center operators readily adopt the idea of logically centralized control, like SDN.

SDN's clean separation between a data plane and a software-based control plane is reflected in data center architectures as well.

<br/>

### Virtualization

`Virtual machines (VMs)` decoupled the applications running software from the physical hardware.

This decoupling made it possible to migrate VMs seamlessly between physical servers in different racks.

Standard Ethernet and IP protocols limit how VMs can be moved while keeping active network connections between servers.

One solution is to treat the entire data center network as a single, flat, layer-2 network.

To get the same effect as if every host were connected to a single switch, ARP is modified to use a DNS-style query system instead of broadcasts, and a directory maintains the mapping between the IP address assigned to each VM and the physical switch it's currently connected to in the data center network.

<br/>

### Physical Constraints

Unlike the wide-area Internet, data center networks operate in high-capacity, ultra-low-latency environments.

So in a data center, if buffers are small, congestion control protocols such as TCP don't work efficiently.

Loss recovery and timeouts make a data center very inefficient, so congestion control protocols have to react quickly and operate at ultra-low latency.

To address this, approaches ranging from TCP variants tailored to data centers to implementing RDMA (Remote Direct Memory Access) over standard Ethernet have been proposed and deployed.

<br/>

### Hardware Modularity and Customization

Another major trend is `modular data centers (MDCs)` based on `shipping containers`.

In an MDC, a mini data center is built inside a standard 12-meter shipping container, and the container is then shipped to the data center site.

Each container is densely packed with up to a few thousand hosts across dozens of racks.

At the data center site, multiple containers are interconnected with each other and with the Internet.

Once a prefabricated container is installed at a data center, it can be hard to service.

So containers are designed for graceful performance degradation: when enough components have failed and performance drops below a threshold, the whole container is removed and replaced.

<br/>

An MDC has two kinds of networks: the internal network inside each container, and the core network that connects the containers.

However, designing a core network that interconnects hundreds of thousands of containers while still providing high host-to-host bandwidth between containers for typical workloads remains a challenge.

<br/>

### Continuous Building and Customization

Large cloud providers keep building or customizing everything in their data centers: network adapters, switches, routers, TORs, software, and networking protocols.

<br/>

### Improving Reliability

They improve reliability by replicating data centers in nearby buildings to create availability zones.
