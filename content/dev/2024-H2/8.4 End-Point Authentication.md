# 8.4 End-Point Authentication

**End-point authentication** is the process of one entity proving its identity to another over a computer network.

For example, an email user can prove their identity to a mail server.

Mutual authentication must be performed based solely on the messages and data exchanged as part of the authentication protocol.

<br/>

Most authentication protocols run before any other protocol.

In other words, the real work happens after authentication.

<br/>

### Authentication protocol ap2.0

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217313217-cf72d0bc-f97f-4972-a511-5e2da76bc682.png" alt="2.0"></p>

If the sender always communicates from a well-known network address (IP address), the receiver can authenticate the sender by checking that the source address of the IP datagram carrying the authentication message matches the sender's IP address.

But this isn't secure, because anyone can create an IP datagram, put whatever source IP address they want in it, and send it to a router.

<br/>

For example, an intruder can send data with a fake source address — a form of `IP spoofing`.

Preventing the intruder from changing the source address would fix this, but that can't be enforced.

<br/>

### Authentication protocol ap3.0

<p align="center"><img width="500" src="https://user-images.githubusercontent.com/76640167/217313211-f9251e8f-3080-4b61-98b1-89a55323f35e.png" alt="3.0"></p>

The authenticator and the person being authenticated can use a shared secret password.

Many services, such as Gmail and Facebook, use password authentication.

But this protocol isn't secure either.

If an intruder eavesdrops on the sender's communication, they can learn the sender's password and later pretend to be the sender.

<br/>

### Authentication protocol ap3.1

Encrypting the password prevents it from being overheard.

The sender and receiver can share a symmetric secret key to encrypt and decrypt the password.

<br/>

But the receiver is still exposed to a `playback attack`.

The intruder eavesdrops, records the sender's encrypted password, and later sends it to the receiver as-is.

In other words, the intruder can pretend to be the sender.

<br/>

### Authentication protocol ap4.0

<p align="center"><img width="250" src="https://user-images.githubusercontent.com/76640167/217313200-84dafe6c-0188-4aad-8c92-4f84520367b8.png" alt="4.0"></p>

A `nonce` is a number that a protocol uses only once in a lifetime.

**Scenario**

1. The sender sends a message.
2. The receiver picks a nonce R and sends it to the sender.
3. The sender encrypts the nonce with the symmetric secret key and sends the encrypted nonce K(R) to the receiver.
    - The next time this sender communicates, R will be different, but since the sender knows the secret key, it can be authenticated again.
    - An intruder, however, doesn't know the secret key and can't encrypt it.
4. Since the other party knows the symmetric secret key, the receiver confirms it's really them.
