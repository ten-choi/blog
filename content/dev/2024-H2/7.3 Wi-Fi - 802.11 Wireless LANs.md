# 7.3 Wi-Fi: 802.11 Wireless LANs

<br/>

Many `wireless LAN` technologies and standards were developed in the 1990s,  
but the most successful of them, the `IEEE 802.11 wireless LAN` better known as <b>Wi-Fi</b>, ended up unifying the field.

<br/>

## The IEEE 802.11 Standards

<p align="center"><img width="600" alt="Summary of IEEE 802.11 standards" src="https://user-images.githubusercontent.com/86337233/216346578-d86272d3-836a-45f4-8708-a840c9774c4a.png">

<br/>
<br/>

#### 802.11b, g, n, ac, ax

- Intended for WLANs, typically operating over distances of less than 70 m
- They are `backward compatible` with earlier standards.  
  For example, a mobile device that only supports 802.11g can still interact with an 802.11ac or 802.11ax base station.
- They all use the same medium access protocol, `CSMA/CA`.

<br/>

#### 802.11af, ah

- Intended for IoT, sensor networks, and metering applications (operating over longer distances)

<br/>
<br/>

### Frequency Ranges

802.11 wireless LAN devices operate in two frequency ranges.

<br/>

#### 2.4 GHz band

- 2.4–2.485 GHz frequency range
- An unlicensed frequency band
- In this range, 802.11 devices compete for spectrum with 2.4 GHz cordless phones and home appliances.

<br/>

#### 5 GHz band

- 5.1–5.8 GHz frequency range
- At the same power level, it has a shorter transmission range than the 2.4 GHz band and suffers more from multipath propagation.

<br/>
<br/>

### Antennas

The `802.11n, 802.11ac, and 802.11ax standards` use `MIMO (multiple-input multiple-output) antennas`.

This means there are two or more antennas on both the sending and receiving sides, each transmitting/receiving different signals.

<br/>

`802.11ac and 802.11ax base stations` can transmit to multiple stations simultaneously,  
and they use `smart antennas` that can dynamically beamform toward the receiver depending on the destination.

This reduces interference and extends the reach at a given data rate.

<br/>
<br/>
<br/>

# 7.3.1 The 802.11 WLAN Architecture

The figure below shows the key components of the 802.11 wireless LAN architecture.

<br/>

<p align="center"><img width="550" alt="IEEE 802.11 LAN architecture" src="https://user-images.githubusercontent.com/86337233/216346557-03035043-aef6-43e7-92c5-55f5bfc265ba.png">

<br/>
<br/>

### BSS (basic service set)

- The fundamental building block of the 802.11 architecture
- Consists of
    - one or more `wireless stations`
    - one base station, i.e., an `AP (access point)`
- In a typical home network, you need both an AP and a router to connect the BSS to the Internet.

<br/>

### MAC Addresses

- Each **802.11 wireless station** has a 6-byte MAC address.
    - The MAC address is stored in the firmware of the station's adapter (the 802.11 network interface card).
- **Each AP** also has a MAC address for its wireless interface.
- MAC addresses are administered by the IEEE and are, in theory, globally unique.

<br/>

### Infrastructure Wireless LAN

- A wireless LAN with APs
- `Network infrastructure`: the APs plus the wired Ethernet that connects them to an Internet router.

<br/>

#### Ad Hoc Networks

- Refers to the case where **there is no central control and no infrastructure connecting to an outside network**.
    - e.g., people with laptops meeting in a place with no centrally controlled AP (a meeting room, a train, a car, etc.) and exchanging data
- The network is formed on the fly through connections between nearby mobile devices.
    - Since they can't rely on any pre-existing network infrastructure, nearby devices have to find each other and communicate directly.

<br/>

The figure below shows IEEE 802.11 stations grouping together to form an `ad hoc network`.

<br/>

## Channels and Association

In 802.11, each wireless station **must associate with an AP** before it can send or receive network-layer data.

*All 802.11 standards use association, but we'll discuss the topic specifically in the context of `IEEE 802.11b, g, n, ac, and ax`.*

<br/>

- When a network administrator installs an AP, they assign it a one- or two-word `SSID (Service Set Identifier)`.
- The administrator must also assign the AP a `channel number`.
    - 802.11 operates in the 2.4–2.4835 GHz frequency range.
    - Within this roughly 80 MHz band, 11 partially overlapping channels are defined,  
      so two channels **don't overlap only if they're separated by four or more channels.**

<br/>

### WiFi Jungle

> Any location where a `wireless station` receives a sufficiently strong signal **from two or more APs**

These APs may belong to different IP subnets and may have been assigned channels independently.

<br/>

To access the Internet, a wireless station has to join exactly one subnet, so **it must associate with exactly one AP.**

(Association = the wireless station creating a virtual wire to the AP)

<br/>

1. The 802.11 standard requires each AP to periodically send `beacon frames`.
    - A beacon frame contains the AP's `SSID` and `MAC address`.


2. The wireless station scans the 11 channels looking for beacon frames from nearby APs.


3. Having **learned about the available APs from the beacon frames**, the wireless station picks one AP to associate with.
    - The 802.11 standard doesn't define an algorithm for choosing among the available APs;  
      that's left to the designers of the wireless station's firmware or software.
    - Typically, the AP with the strongest beacon signal is chosen.

<br/>

### Passive Scanning and Active Scanning

`Passive scanning`: finding a channel **by receiving beacon frames**

<br/>

<p align="center"><img width="400" alt="Passive scanning" src="https://user-images.githubusercontent.com/86337233/216346581-f73d0c24-fbfe-4c83-b6b7-19d4aad301b5.png">

1. The APs send beacon frames.
2. H1 sends an association request message to the selected AP.
3. The selected AP sends an association response message to H1.

<br/>
<br/>


A wireless host can also perform active scanning.

`Active scanning`: the wireless station **broadcasts a probe frame** to all APs within range

<br/>

<p align="center"><img width="400" alt="Active scanning" src="https://user-images.githubusercontent.com/86337233/216346587-53d80b6c-b86f-42ae-b4df-a8b8d6993e7e.png">

1. H1 broadcasts a `probe request frame`.
2. `Probe response messages` arrive from the APs.
3. H1 sends an association request message to the selected AP.
4. The selected AP sends an association response message to H1.

<br/>

An AP that responds to the station's initial probe request doesn't know which of the responding APs will be chosen, so a second `request/response handshake` is needed.

<br/>
<br/>


After associating with an AP, the wireless station sends a `DHCP discovery message` into the subnet via the associated AP to obtain an `IP address on the AP's subnet`.

Once it has an address, the rest of the Internet sees the wireless station simply as a host with an IP address in the selected AP's subnet.

<br/>

To associate with a particular AP, a wireless station may also need to `authenticate` itself to that AP.

- e.g., granting access to the wireless network based on the station's MAC address / entering a username and password
- The AP communicates with an `authentication server`, relaying information between the wireless end station and the authentication server using protocols such as RADIUS or DIAMETER.

<br/>
<br/>
<br/>

# 7.3.2 The 802.11 MAC Protocol

Once a wireless station is associated with an AP, it can start sending and receiving data frames to and from the AP.

However, since **multiple stations, including the AP itself, may want to transmit data frames over the same channel at the same time,**
a `multiple access protocol` is needed to coordinate transmissions.

<br/>

Multiple access protocols fall into three broad categories:

- Channel partitioning (e.g., CDMA)
- **Random access**
- Taking turns

<br/>

Inspired by the huge success of random access protocols in Ethernet, wireless LANs also use a random access protocol.

The random access protocol used in 802.11 wireless LANs is `CSMA/CA (carrier sense multiple access with collision avoidance)`.

That is, a station senses the channel before transmitting and refrains from transmitting if the channel is busy.

<br/>

Both Ethernet and 802.11 use carrier-sensing random access,  
but their `MAC (Medium Access Control) protocols` differ.

1. Instead of collision detection, 802.11 uses `collision avoidance` techniques.
    - Why
        - Collision detection requires being able to transmit (your own signal) and receive (to tell whether another station is transmitting) at the same time.  
          In an 802.11 adapter, **the received signal is typically very weak compared to the transmitted signal**, so building hardware that can detect collisions while handling both is expensive.
        - Even if an adapter could transmit and listen at the same time and abort when it sensed another station using the channel,  
          it might still fail to detect collisions because of the `hidden terminal problem` and `fading`.
    - So in an 802.11 wireless LAN, once a station starts transmitting a frame, **it transmits the whole frame and cannot abort.**
        - Transmitting entire frames when collisions are frequent can significantly degrade the multiple access protocol's performance, so several collision avoidance techniques are used.


2. 802.11 uses a `link-layer ARQ (acknowledgment/retransmission) scheme`.

<br/>

### Link-Layer Acknowledgment

In a wireless LAN, a frame sent by the sending station may not reach the destination station intact for various reasons (hidden terminals, fading, etc.).  
To deal with this, the 802.11 MAC uses `link-layer acknowledgments`.

<br/>

<p align="center"><img width="400" alt="Link-layer ACK" src="https://user-images.githubusercontent.com/86337233/216346591-8c3a7193-2f6e-4a81-9cf5-cf95bbfd8159.png">

<br/>
<br/>

1. When the destination station **receives a frame that passes the CRC check**,  
   it waits a short period called the `SIFS (Short Inter-Frame Spacing)` and then sends an `ACK frame` back to the sender.


2. (1) If the sending station doesn't receive an ACK within a given time, it assumes an error has occurred.

   (2) The sending station then accesses the channel again using the `CSMA/CA protocol` and retransmits the frame.


3. If it still hasn't received an ACK after a fixed number of retransmissions, the sending station gives up and discards the frame.

<br/>

### The 802.11 CSMA/CA Protocol

Suppose a station (a wireless device or an AP) has a frame to transmit.

1. If the station **senses that the channel is idle**, it waits a short period called the `DIFS (Distributed Inter-frame Space)` and then transmits the frame.


2. Otherwise, **if the channel is busy**, the station picks a random wait time using a `backoff scheme` (see Section 6.3.2).
    - After DIFS, the counter for that wait time counts down while **the channel is sensed idle**,  
      and stays frozen while **the channel is sensed busy**.


3. **When the counter reaches zero, the station transmits the entire frame and then waits for an ACK.**
    - The counter can only reach zero while the channel is idle.


4. (1) **If it receives an ACK**, the sending station knows its frame was correctly received by the destination station.  
   → If the station has another frame to send, it runs the CSMA/CA protocol starting at step 2.

   (2) **If it doesn't receive an ACK**, the sending station picks a random value from a larger range and repeats the backoff process from step 2.

<br/>

---

<br/>

- Ethernet's `CSMA/CD (collision detection) multiple access protocol`  
  : a station starts transmitting as soon as it senses the channel is idle.


- 802.11's `CSMA/CA (collision avoidance) protocol`  
  : even when a station senses the channel is idle, it picks a random backoff value and goes through a **countdown**, delaying its transmission.

<br/>
<br/>

> Consider two stations, each with a frame to send, that **hold off because they sense a third station is already transmitting.**

<br/>

With Ethernet's `CSMA/CD`, both stations start transmitting right after the third station finishes.

- This causes a collision, and under CSMA/CD both stations **abort their transmissions immediately.**
- Because **they don't send the rest of the collided frames**, unnecessary transmissions are avoided and the damage stays small.

<br/>

802.11 neither detects collisions nor aborts transmissions.

- Since even collided frames are transmitted in full, **802.11's goal is to avoid collisions whenever possible.**


- **When two stations sense that the channel is busy**, they avoid collisions as follows:
    1. Each performs `random backoff` and picks a random backoff value.
    2. If their backoff times differ, once the channel becomes idle
        1. one of the two competing stations starts transmitting before the other,
        2. the "losing station" senses the "winning station's" signal, freezes its counter,
        3. and waits until the winning station finishes its transmission.


- Even so, collisions can still happen if the two stations are hidden from each other or if their random backoff values are too close.

<br/>
<br/>

## Dealing with Hidden Terminals: RTS and CTS

The 802.11 MAC protocol also offers an optional reservation scheme that helps avoid collisions even when `hidden terminals` are present.

<br/>

In the scenario below there are two wireless stations (H1, H2) and one AP.

Both wireless stations are within range of the same AP and associated with it,  
but because of `fading`, **each station is visible to the AP yet hidden from the other.**

<br/>

<p align="center"><img width="460" alt="Hidden terminals" src="https://user-images.githubusercontent.com/86337233/216346594-2f41f136-a37b-4f9e-a5cf-e69dbe908482.png">

<br/>
<br/>

*Why are hidden terminals a problem?*

Suppose station H1 is transmitting a frame to the AP, and while H1 is transmitting, station H2 wants to send to the AP.

Since H2 can't hear H1's transmission, it waits for DIFS and then sends its DATA frame, causing a collision,  
and the channel is wasted for the entire duration of both H1's and H2's transmissions.

<br/>
<br/>


To solve this, the IEEE 802.11 protocol lets stations **reserve** channel access  
by exchanging a short `RTS (Request to Send) control frame` and a short `CTS (Clear to Send) control frame`.

<br/>

1. When a sender wants to transmit a DATA frame, it first **sends an `RTS frame` to the AP**,  
   indicating the total time needed to transmit the DATA frame and the ACK frame.


2. When the AP receives the RTS, it responds by **broadcasting a `CTS frame` to all stations in range** (including the sender).
    - It gives the sender explicit permission to transmit.
    - It tells the other stations not to transmit for the reserved duration.

<br/>

<p align="center"><img width="450" alt="RTS, CTS" src="https://user-images.githubusercontent.com/86337233/216346598-689d3480-06c2-4faf-aaaa-06b40574ff2a.png">

<br/>
<br/>

Using RTS and CTS frames improves performance in two ways:

- The hidden station problem is mitigated, since a long DATA frame is transmitted only after the channel has been reserved.
- RTS and CTS frames are short, so collisions involving them only last for the short RTS/CTS transmission time.  
  Once the RTS and CTS frames are transmitted correctly, the following DATA and ACK frames go through without collisions.

<br/>

However, they also introduce delay and consume channel resources.

So in practice, wireless stations set an `RTS threshold`,  
**using the RTS/CTS exchange to reserve the channel only when transmitting DATA frames longer than the threshold.**

<br/>

### Using 802.11 as a Point-to-Point Link

If two nodes each have a `directional antenna`,  
they can **point the antennas at each other to form a point-to-point link** and run the 802.11 protocol over it.

By combining inexpensive 802.11 hardware with directional antennas and increased transmit power,  
802.11 can serve as a cheap way to provide wireless point-to-point connections over tens of kilometers.

<br/>
<br/>
<br/>

The 802.11 frame is similar to the Ethernet frame, but it has several fields specific to wireless links.

<br/>

The figure below shows the 802.11 frame.  
The number above each field is its length in **bytes**.

The numbers above the subfields of the `Frame Control field` are the subfield lengths in **bits**.

<br/>

<p align="center"><img width="670" alt="802.11 frame" src="https://user-images.githubusercontent.com/86337233/216346605-ecec2465-773a-4651-8241-2d3f45e857ee.png">

<br/>
<br/>
<br/>

## Payload and CRC Fields

- The `payload` is usually an IP datagram or an ARP packet.  
  (Up to 2,312 bytes are allowed; it carries one datagram or ARP packet.)


- The 32-bit `CRC` lets **the receiver detect bit errors in the received 802.11 frame.**  
  (Bit errors are far more common in wireless LANs than in wired LANs, so CRC is even more useful there.)

<br/>
<br/>

## Address Fields

The most striking difference in the 802.11 frame is that it has **four address fields**.

Each address field can hold a 6-byte MAC address.

<br/>

Why are four address fields needed?

- Three addresses are needed for `internetworking`.
    - e.g., when a wireless station sends a network-layer datagram through an AP to a router interface
- The fourth address is used in `ad hoc network mode`.

<br/>

The 802.11 standard defines the first three address fields as follows.

<br/>

### Address 2

- The MAC address of the station **transmitting the frame**
- e.g.,
    - When a wireless station transmits a frame, that station's MAC address goes into this field.
    - When an AP transmits a frame, the AP's MAC address goes into this field.

<br/>

### Address 1

- The MAC address of the wireless station **receiving the frame**.
- e.g.,
    - When a mobile wireless station transmits a frame, Address 1 holds the MAC address of the destination AP.
    - When an AP transmits a frame, Address 1 holds the MAC address of the destination wireless station.

<br/>

### Address 3

- A BSS (the AP plus its wireless stations) is part of a subnet, and that subnet connects to other subnets through a router interface.
- Address 3 holds the MAC address of this **router interface**.

<br/>

> 💡 Address 3 plays a crucial role in internetworking the BSS with a wired LAN.

<br/>
<br/>


Let's look at an example.

<br/>

<p align="center"><img width="540" alt="Use of the address fields" src="https://user-images.githubusercontent.com/86337233/216346608-79ea04e3-4823-4353-8233-78c075dd9a92.png">

<br/>
<br/>

- There are two APs, each responsible for a number of wireless stations.
- Each AP is directly connected to a router, which connects to the global Internet.
- **An AP is a link-layer device, so it has no network-layer (IP) functionality and doesn't understand IP addresses.**

<br/>
<br/>

> 1️⃣ Suppose a datagram is being sent from `router interface R1` to `wireless station H1`.

The router doesn't know there's an AP between itself and H1; it just sees H1 as a host on one of its attached subnets.

<br/>

1. (1) Knowing H1's IP address from the datagram's destination address, the router uses `ARP` to determine H1's MAC address.

   (2) Having obtained H1's MAC address, router interface R1 encapsulates the datagram in an `Ethernet frame`.

    - Source address field: R1's MAC address
    - Destination address field: H1's MAC address


2. When the Ethernet frame arrives at the AP,  
   the AP **converts the 802.3 Ethernet frame into an** `802.11 frame` **before transmitting it over the wireless channel.**
    - Address 1 field: H1's MAC address
    - Address 2 field: the AP's own MAC address
    - Address 3 field: R1's MAC address

<br/>

This way, H1 can learn from Address 3 the MAC address of the router interface that sent the datagram into the subnet.

<br/>
<br/>


> 2️⃣ Now suppose `wireless station H1` sends a datagram back to R1 in response.

1. H1 creates an `802.11 frame`.
    - Address 1 field: the AP's MAC address
    - Address 2 field: H1's MAC address
    - Address 3 field: R1's MAC address


2. When the AP receives this 802.11 frame, it converts it into an `Ethernet frame`.
    - Source address field: H1's MAC address
    - Destination address field: R1's MAC address

<br/>

So Address 3 lets the AP determine the destination MAC address when it builds the Ethernet frame.

<br/>
<br/>

## Sequence Number, Duration, and Frame Control Fields

In 802.11, whenever a station correctly receives a frame from another station, it sends back an ACK.

Since ACKs can be lost, the sending station may send the same frame multiple times;  
by using sequence numbers in the `Sequence Number field`, the receiver can **distinguish a newly transmitted frame from a retransmitted one**.

<br/>

In the 802.11 protocol, the sending station can **reserve the channel** for a period that covers the time to transmit its data frame and the time to transmit the ACK.

For data frames as well as RTS and CTS frames, this duration value is carried in the frame's `Duration field`.

<br/>

The `Frame Control field` consists of several subfields.

- `Type` and `Subtype` fields: used to distinguish association, RTS, CTS, ACK, and data frames.


- `To` and `From` fields: used to define the meaning of the address fields.
    - The meaning of the address fields depends on  
      (1) whether ad hoc or infrastructure mode is used, and  
      (2) in infrastructure mode, whether the frame is sent by a wireless station or by the AP.


- `WEP field`: indicates whether encryption is used.

<br/>
<br/>
<br/>

# 7.3.4 Mobility in the Same IP Subnet

To increase the physical range of a wireless LAN, multiple BSSs are sometimes deployed within the same IP subnet.

This raises a mobility question: how can a wireless station move seamlessly from one BSS to another while keeping its ongoing TCP sessions?

<br/>

<p align="center"><img width="450" alt="Mobility in the same subnet" src="https://user-images.githubusercontent.com/86337233/216346612-bb10d23c-7192-4800-b658-3594934a99fb.png">

<br/>
<br/>

In the figure above, the device connecting the two BSSs is not a router, and all stations in both BSSs, including the APs, belong to the same IP subnet.

So when host H1 moves from BSS1 to BSS2, H1's IP address stays the same, and its ongoing TCP connections can be maintained.

<br/>

If the interconnecting device were a router, H1 would have to get a new IP address for the subnet it moved into,  
which may mean suspending or terminating its ongoing TCP connections.

→ This is handled with network-layer mobility protocols such as mobile IP.

<br/>

### From the Host's and AP's Point of View

1. As H1 moves away from AP1, it detects that AP1's signal is weakening and starts scanning for a stronger signal.
2. When H1 receives `beacon frames` from AP2, it disassociates from AP1 and associates with AP2, keeping its IP address and ongoing TCP sessions.

<br/>

### From the Switch's Point of View

A switch is "self-learning" and builds its forwarding table automatically,  
but it can't by itself support users moving between BSSs while keeping their TCP connections.

- While H1 is in BSS1, H1's datagrams must be forwarded to AP1.
- While H1 is in BSS2, H1's datagrams must be forwarded to AP2.

<br/>

1. After H1 sets up a new association with BSS2,
2. AP2 **broadcasts an** `Ethernet frame` **with H1 as the source address to the switch**.
3. On receiving this frame, the switch updates its forwarding table so that H1 can be reached via AP2.

<br/>
<br/>
<br/>

# 7.3.5 Advanced Features in 802.11

### 802.11 Rate Adaptation

As we saw earlier, different modulation schemes, each with a different transmission rate, suit different SNR conditions.

<br/>

Consider an 802.11 mobile user who is 20 m from the base station and has a **high SNR**.

- The user can use a physical-layer modulation scheme with a high transmission rate while keeping the BER low.
- But as the user walks away from the base station and the SNR drops, the BER will become unacceptably high.

<br/>

That's why some 802.11 implementations support `rate adaptation`.

It adaptively selects the physical-layer modulation scheme based on current or recent channel conditions.

(Similar to TCP congestion control)

<br/>
<br/>

### Power Management

The 802.11 standard provides `power management` capabilities that let a node minimize the time it spends  
on sensing, transmitting, receiving, and other power-hungry functions.

<br/>

1. A node explicitly switches between a `sleep state` and a `wake state`.


2. A node tells the AP it is going to sleep by setting the `power-management bit` in an 802.11 frame to 1.


3. A timer in the node is then set so that the node wakes up just before the AP is scheduled to send its beacon frame.


4. The AP stops sending frames to the sleeping node and buffers any frames destined for that host to send later.


5. The sleeping node wakes up **just before the AP sends its beacon frame** and quickly (in 250 µs) enters the fully `active state`.
    - The AP's beacon frame contains a list of nodes that have frames buffered at the AP.
    - If the node isn't on that list, it can go back to sleep.
    - Otherwise, the node explicitly requests the buffered frames by sending a polling message to the AP.

<br/>
<br/>

# 7.3.6 Personal Area Networks: Bluetooth

A `Bluetooth network` operates over short ranges (tens of meters or less), at low power and low cost.

That's why it's also called a `WPAN (wireless personal area network)` or a `piconet`.

<br/>

Bluetooth networks are packed with `link-level networking techniques`:

- Time-division multiplexing (TDM) and frequency division
- Random backoff
- Polling
- Error detection and correction
- Reliable data transfer using ACKs/NAKs

<br/>
<br/>

## Frequency Band

Bluetooth operates in the unlicensed `2.4 GHz band`, part of the `radio ISM (Industrial, Scientific, Medical) band`.

Because it competes with home appliances using the same band (microwave ovens, cordless phones, etc.), **it was explicitly designed with noise and interference in mind.**

<br/>
<br/>

## Time-Division Multiplexing (TDM)

The Bluetooth wireless channel operates in a `TDM` fashion with **time slots of 625 microseconds**.

- In each time slot, the sender transmits on one of 79 channels, changing the frequency channel from slot to slot.
- The next frequency channel is chosen in a `pseudo-random` manner.

<br/>

This form of channel hopping is known as `frequency-hopping spread spectrum (FHSS)`.

It confines interference from other devices and appliances using the ISM band to only some of the time slots.

<br/>
<br/>

## Ad Hoc Networks

Bluetooth networks are `ad hoc networks` with no infrastructure (e.g., an AP).

Instead, as shown below, devices must organize **themselves** into a piconet of up to 8 active nodes.

<br/>

<p align="center"><img width="460" alt="Bluetooth" src="https://user-images.githubusercontent.com/86337233/216346617-a7011a6a-a3dd-4fd2-8650-bb091e3ca10e.png">

<br/>
<br/>

- One of the devices is designated as the `centralized controller node`, and the rest become clients.


- Besides the 8 active devices, a piconet can contain up to 255 `"parked" devices`.
    - These are often asleep to save power.
    - Sleeping devices periodically wake up, according to a schedule, to receive `beacon messages from the centralized controller node`.
    - They can't communicate until the centralized controller node changes their status to active.

<br/>

### Centralized Controller Node

- Controls the other nodes in the piconet:
    - Manages the clock that determines time slot boundaries
    - Provides the frequency-hopping sequence
    - Controls client entry into the piconet
    - Controls the transmit power of client devices (100 mW, 2.5 mW, 1 mW)


- **Grants transmission rights** to clients admitted to the network **using** `polling`.

<br/>
<br/>

## The Neighbor Discovery Problem

A Bluetooth ad hoc network has to organize **itself** without an AP.

<br/>

1. To form a Bluetooth network, the `centralized controller node` must first **determine which other Bluetooth nodes are within range.**
    - The centralized controller node does this by broadcasting `a series of 32 inquiry messages`, each on a different channel.
    - A client device picks one of the frequencies and listens for these inquiry messages.


2. (1) When a `client device` receives an inquiry message,  
   (2) it waits a random time between 0 and 0.3 seconds to avoid colliding with other responding nodes,  
   (3) then sends a response message containing its ID to the centralized controller node.


3. `Bluetooth paging`
    - Once the centralized controller node has discovered all the potential client nodes nearby, it invites the clients that want to join the piconet.
    - Process
        1. The centralized controller node starts the paging phase by again sending `32 identical paging invitation messages`, addressed to each client.
            - Since the clients haven't learned the frequency-hopping sequence yet, the messages are sent on different frequencies.
        2. When a client responds to the invitation with an ACK, the centralized controller node sends the clients:
            - Frequency-hopping information
            - Clock synchronization information
            - Addresses of the active members
        3. The centralized controller node then polls each client to confirm it is connected to the network,  
           and they begin communicating using the `frequency-hopping pattern`.
