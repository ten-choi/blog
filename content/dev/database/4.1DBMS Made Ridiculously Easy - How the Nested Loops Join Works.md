# 4.1 How the Nested Loops Join Works

There are three join methods: **NL join, hash join, and sort merge join**.

MySQL supports different join methods depending on the version.

- **Up to 5.7** → NL join only
- **From 8.0** → hash join is supported as well

[MySQL official docs — Hash Join](https://dev.mysql.com/doc/refman/8.0/en/hash-joins.html)

<br>

## 4.1.1 The NL join mechanism

The NL join (Nested Loop Join) matches two tables with — exactly as the name says — a **nested loop**.

<img width="800" src="https://user-images.githubusercontent.com/60383031/145702715-98dc6fa0-13d7-4105-bd01-638c52caaf71.png">

The join proceeds like this.

- (1) Scan Table A one row at a time.
    - Here, Table A is called the **Driving Table** (or Outer Table).


- (2) Every time a row is pulled from the Outer Table, scan Table B and return the rows that match the join condition.
    - Here, Table B is called the **Inner Table**.


- (3) Repeat steps 1–2 until the Outer Table runs out of rows.

## 4.1.3 Choosing the right join method

When picking a join, approach it in this order.

1. **Start by considering the NL join.** For small-volume joins it's almost always optimal.
2. If performance falls short, follow the NL join tuning checkpoints and first find **where excessive random access is happening**.
3. If that still doesn't cut it, look into a **sort merge join or a hash join**.

## 4.1.4 NL join characteristics, summarized

1. It's a **random-access-heavy** join method. That's why it loses efficiency when joining large volumes of data.
2. Because it processes one record at a time in sequence, it can deliver a very fast response time for **small-volume joins** or in situations where **partial range processing** is possible.

---

### 📝 One-line takeaway

> **"The NL join reads the outer table row by row and probes the inner table's index each time — unbeatable for small, well-indexed joins, but its random access adds up fast on big ones."**
