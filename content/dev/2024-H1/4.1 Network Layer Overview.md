# 4.1 Network Layer Overview

<p align="center"><img width="500" alt="Network layer diagram" src="https://user-images.githubusercontent.com/76640167/212541870-2c4951cb-167a-48f2-a69d-b6dc44c6d656.png">

Given two hosts, H1 and H2, the network layer takes a transport-layer segment from one host and delivers it up to the transport layer of H2.

<br/>

Routers don't support the transport or application layers, so in a router's protocol stack there is nothing above the network layer.

Every router has a data plane and a control plane.
- `Data plane`: forwards datagrams from an input link to an output link.
- `Control plane`: coordinates local, per-router forwarding so that datagrams travel end to end from the source host to the destination host.

<br/>

## 4.1.1 Forwarding and Routing: The Data and Control Planes

> 💡 The fundamental job of the network layer is to move packets from a sending host to a receiving host.

Two key functions make this possible:
- `Forwarding`: When a packet arrives on a router's input link, the router must move it to the appropriate output link. Forwarding runs in the data plane and works on very short timescales (typically a few nanoseconds), so it's usually implemented in hardware.
- `Routing`: When a sender transmits packets to a receiver, the network layer must determine the path they take. The algorithms that compute these paths are called `routing algorithms`. Determining the end-to-end path of a datagram from source to destination across the whole network takes much longer, so it runs in software.

<br/>

### Forwarding Table

<p align="center"><img width="500" alt="Forwarding table" src="https://user-images.githubusercontent.com/76640167/212542030-df6ba632-c5a2-4460-959e-347960dd256f.png">

A router forwards a packet by **using a field value in the arriving packet's header as an index into its `forwarding table`**.

The value stored in the forwarding table entry for that header value tells you **the router's outgoing link interface the packet should be forwarded to**.

<br/>

### Control Plane: The Traditional Approach

The routing algorithm runs in each and every router, and every router has both forwarding and routing functions.

The routing algorithm in one router communicates with the routing algorithms in other routers to compute the values in its forwarding table.

This communication happens by exchanging routing messages containing routing information, according to a routing protocol.

(Covered in more detail in Chapter 5.)

<br/>

### Control Plane: The SDN Approach

<p align="center"><img width="500" alt="SDN forwarding table" src="https://user-images.githubusercontent.com/76640167/212543852-6720ef7e-0ff9-46f5-bdf3-1771335eaca5.png">

The figure above shows a different approach: a remote controller, physically separate from the routers, computes and distributes the forwarding tables each router will use.

The routers communicate with the remote controller by exchanging messages containing forwarding tables and other routing information.

<br/>

**While the remote controller computes and distributes forwarding tables, the routing devices only perform forwarding.**

In other words, when the network is **software-defined**, the controller that computes the `forwarding tables` **interacts with the routers and runs in software**.

This approach, where the remote controller sits apart from the routers in a remote data center with high reliability and redundancy, is at the heart of `SDN (software-defined networking)`.

(Covered in more detail in Chapter 5.)

<br/>

## 4.1.2 Network Service Model

Services the network layer could provide:
- `Guaranteed delivery`: guarantees that a packet sent by the source host will eventually arrive at the destination host.
- `Guaranteed delivery with bounded delay`: not only guarantees delivery, but delivers within a specified host-to-host delay bound (e.g., within 100 ms).
- `In-order packet delivery`: guarantees that packets arrive at the destination in the order they were sent.
- `Guaranteed minimal bandwidth`: emulates a transmission link of a specified bit rate between the sending and receiving hosts. As long as the sending host transmits bits below that rate, all packets are delivered to the destination host.
- `Security`: the network layer could encrypt all datagrams at the source host and decrypt them at the destination host, providing confidentiality for all transport-layer segments.

There are many other variations as well.

The Internet's network layer provides a single service known as `best-effort service`.

Characteristics of best-effort service:
- Packets are not guaranteed to be received in the order they were sent.
- Packets are not guaranteed to be delivered to the destination at all.
- There is no guarantee on end-to-end delay.
- There is no guaranteed minimum bandwidth.

Better service models have been defined and implemented to address these limitations, but the Internet's best-effort network layer has proven good enough to enable a surprisingly broad range of applications.
