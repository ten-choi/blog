# 5.4 Routing Among Internet Service Providers (ISPs): BGP

When routing a packet **across multiple ASs**  
(e.g., a smartphone in Korea sending data to a data center in Silicon Valley),  
we need an `inter-autonomous system routing protocol`.

<br/>

Communicating ASs must run the same inter-AS routing protocol.

In fact, every AS in the Internet uses the `Border Gateway Protocol (BGP)`,  
a **decentralized, asynchronous protocol** that can be seen as stemming from the same lineage as distance-vector routing.

<br/>
<br/>

## 5.4.1 The Role of BGP

For `destinations within the same AS`, the entries in a router's forwarding table are determined by the AS's intra-AS routing protocol.

<br/>

But when the destination is outside the AS, we need `BGP`.

In BGP, packets are forwarded toward `address prefixes`, the leading portion of an address written in `CIDR (Classless Inter-Domain Routing) format`.

Each prefix represents a subnet or a collection of subnets. (e.g., 139.16.68/22)

<br/>

A router's forwarding table will have entries of the form `(x, I)`:

- `x`: an address prefix (e.g., 139.16.68/22)
- `I`: the interface number of one of the router's interfaces

<br/>

---

<br/>

As an inter-AS routing protocol, BGP provides each router with a means to:

1. Obtain subnet prefix reachability information from neighboring ASs.
    - **In particular, it lets each subnet advertise its existence to the rest of the Internet.**


2. Determine the best routes to subnet address prefixes.
    - A router may learn about two or more different routes to a specific address prefix.
    - To determine the best route, the router runs BGP's route-selection procedure.

<br/>
<br/>

## 5.4.2 Advertising BGP Route Information

The simple network below has three autonomous systems, `AS1`, `AS2`, and `AS3`,  
and AS3 includes a subnet with address prefix `x`.

<br/>

<p align="center"><img width="650" alt="Three ASs" src="https://user-images.githubusercontent.com/86337233/213658057-4bb81f7c-590e-4f60-ac3d-2e2bca19d361.png">

<br/>
<br/>
<br/>

Within each AS, each router is either a `gateway router` or an `internal router`.

<br/>

#### Gateway router

- A router on the edge of an AS
- Directly connects to one or more routers in other ASs.
- e.g., `router 1c` in AS1

<br/>

#### Internal router

- Connects only to hosts and routers within its own AS.
- e.g., `routers 1a, 1b, 1d` in AS1

<br/>

---

<br/>

ASs don't actually send messages to each other; **routers do.**

<br/>

#### BGP connection

- In BGP, pairs of routers exchange routing information over `semi-permanent TCP connections` using port `179`.
- All BGP messages are sent over these TCP connections.

<br/>

#### External BGP (eBGP) connection

- A BGP connection that spans **two ASs**

<br/>

#### Internal BGP (iBGP) connection

- A BGP connection between **routers in the same AS**

<br/>

There's typically an `eBGP connection` on each link that directly connects gateway routers in different ASs.

There are also `iBGP connections` between routers within each AS;  
the figure below shows a common configuration with one BGP connection for each pair of routers within an AS.

> iBGP connections don't always correspond to physical links.

<br/>

<p align="center"><img width="650" alt="eBGP, iBGP" src="https://user-images.githubusercontent.com/86337233/213658044-5da300ad-148d-4477-80f7-4833cd79d1eb.png">

<br/>
<br/>


---

<br/>

In the example above, consider the task of advertising **reachability information** for prefix `x` to all routers in AS1 and AS2.

<br/>

Once the following process completes, each router in AS1 and AS2 knows about the existence of x and the AS path to x.

1. First, gateway router 3a sends an `eBGP message` "`AS3 x`" to gateway router 2c.  
   (meaning <b>"x exists and is in AS3"</b>)


2. Gateway router 2c then sends the `iBGP message` "`AS3 x`" **to all the other routers in AS2**, including gateway router 2a.


3. Gateway router 2a sends the `eBGP message` "`AS2 AS3 x`" to gateway router 1c.  
   (meaning "x exists, and you can reach x by **first passing through AS2 and then going to AS3**")


4. Finally, gateway router 1c uses iBGP to send the message "`AS2 AS3 x`" **to all the routers** in AS1.

<br/>

In a real network, there may be many different paths from a given router to a given destination, each passing through a different sequence of ASs.

The figure below adds a physical link from router 1d to router 3d.

In this case, there are two paths from AS1 to x:

1. the path "`AS2 AS3 x`" via router 1c
2. the new path "`AS3 x`" via router 1d

## 5.4.3 Determining the Best Routes

> There may be many paths from a given router to a destination subnet.  
> How does a router **choose** among them? And how does it **configure its forwarding table** accordingly?

<br/>

### BGP terminology

When a router advertises an address prefix across a BGP connection, it includes several `BGP attributes` with it.

In BGP jargon, **a prefix along with its attributes** is called a `route`.

<br/>

#### AS-PATH

- Contains **the list of ASs through which the advertisement has passed**.
    1. When a prefix is passed to an AS,
    2. that AS adds its ASN to the existing list in the `AS-PATH`.


- Used to detect and prevent looping advertisements.
    1. If a router sees that its own AS is contained in the path list,
    2. it rejects the advertisement.

<br/>

#### NEXT-HOP

- **The IP address of the router interface that begins the AS-PATH**

<br/>

e.g.,

<p align="center"><img width="650" alt="Added link" src="https://user-images.githubusercontent.com/86337233/213658063-f56d6a18-67ac-40c4-9ed4-c0e025822fc5.png">

<br/>
<br/>

The NEXT-HOP attribute of the route "`AS2 AS3 x`" from AS1 to x through AS2 is **the IP address of the left interface on router 2a**.

The NEXT-HOP attribute of the route "`AS3 x`" from AS1 to x that bypasses AS2 is **the IP address of the leftmost interface of router 3d**.

<br/>

So each router in AS1 learns about two BGP routes to prefix x:

> IP address of leftmost interface of router 2a; AS2 AS3; x


> IP address of leftmost interface of router 3d; AS3; x

<br/>

The NEXT-HOP attribute is the IP address of a router that **does not belong to AS1**.

However, the subnet containing that IP address **directly attaches to AS1.**

<br/>

### Hot potato routing

> 💡 Among all possible routes, choose the route with **the least cost to the NEXT-HOP router** that begins that route.

<br/>

1. Learn from the inter-AS protocol that subnet x is reachable via multiple gateways.


2. Use routing information from the intra-AS protocol to determine the least-cost path to each gateway.


3. **Hot potato routing: choose the gateway with the smallest least cost.**


4. Determine from the forwarding table the interface I that leads to the least-cost gateway, and add `(x, I)` to the forwarding table.

> When adding an outside-AS destination to a forwarding table,  
> **both** the inter-AS routing protocol (BGP) and the intra-AS routing protocol (e.g., OSPF) are used.

<br/>

e.g.,

<p align="center"><img width="650" alt="Added link" src="https://user-images.githubusercontent.com/86337233/213658063-f56d6a18-67ac-40c4-9ed4-c0e025822fc5.png">

<br/>
<br/>

1. `Router 1b` knows of two BGP routes to subnets whose addresses start with `x`.


2. It **consults its intra-AS routing information** to find the least-cost intra-AS path to each of the `NEXT-HOP routers 2a and 3d`.


3. Among these least-cost paths, it **selects the one with the lowest cost.**

   <br/>

   If cost is defined as the number of links traversed,

    - least cost from router 1b to `router 2a`: 2
    - least cost from router 1b to `router 3d`: 3

   So router 2a is selected.

   <br/>


4. Router 1b looks in its forwarding table (configured by its intra-AS algorithm) to find the interface I that leads to router 2a,  
   and **adds the entry `(x, I)` to its forwarding table.**

<br/>

---

<br/>

> 💡 The basic idea  
> Get packets out of its own AS as quickly as possible (more precisely, at the least possible cost),  
> **without worrying about the cost of the remaining portions of the path outside its AS** to the destination.

<br/>

In other words, hot potato routing is a selfish algorithm that **tries only to reduce the cost within its own AS**.

With it, two routers in the same AS may choose different AS paths to the same destination address.

<br/>

e.g.,  
In the example above, `router 1b` sends packets to subnet x **through AS2**, while `router 1d` sends them **directly to AS3** to reach subnet x.

<br/>

### Route-selection algorithm

In practice, BGP uses a more complicated algorithm that **incorporates hot potato routing**.

<br/>

Given a destination address prefix, all the routes to that destination that the router has learned so far are fed into BGP's route-selection algorithm.

> 💡 If there are two or more routes to the same destination, BGP sequentially applies the following `elimination rules` **until one route remains**.

<br/>

What's added on top of hot potato routing here is that one of the attributes assigned to a route is its `local preference`.

The local preference of a route could have been set by the router or learned from another router in the same AS.

<br/>

1. Routes with the `highest local preference values` are selected.


2. If several routes share the highest local preference value, the route with the `shortest AS-PATH` among them is selected.
    - If this were the only rule for route selection, BGP would be using a `DV algorithm` **for path determination**,
    - with the **number of AS hops** as the distance metric.


3. Hot potato routing is applied to all remaining routes (with the same highest local preference value and the same AS-PATH length).


4. If more than one route still remains, the router uses `BGP identifiers` to select the route.

<br/>

e.g.,
<p align="center"><img width="650" alt="Added link" src="https://user-images.githubusercontent.com/86337233/213658063-f56d6a18-67ac-40c4-9ed4-c0e025822fc5.png">

<br/>
<br/>

There were two BGP routes from `router 1b` to subnet `x` (one through AS2 and one bypassing it),  
and if hot potato routing were applied directly, BGP would route packets through AS2.

However, in the route-selection algorithm above, rule 2 is applied before rule 3, so the route bypassing AS2, **which has a shorter AS-PATH**, is selected.

So this is no longer a selfish algorithm, and as a result end-to-end delay will be reduced.

<br/>
<br/>

## 5.4.4 IP Anycast

BGP is also used to implement the `IP anycast service`.

[Note] `Anycast`: the sending node transmits data to only one node, the nearest among the receivable nodes connected to the network. (works on IPv6)

<br/>

Consider many applications where we want to (1) **replicate the same content on many different, geographically distributed servers,**  
and (2) have each user access the content from the closest server.

e.g., a CDN replicates videos and other content on servers in different countries, and the DNS system can replicate DNS records on DNS servers around the world.

<br/>

In this case, we can use BGP's route-selection algorithm.

<br/>

The figure below shows how IP anycast can be used to send users to the closest CDN server.

<br/>

<p align="center"><img width="670" alt="IP anycast" src="https://user-images.githubusercontent.com/86337233/213658067-9be31c88-86d7-4752-86b0-548f34849ac4.png">

<br/>
<br/>

1. During the IP anycast configuration stage,  
   (1) the CDN company assigns the **same** IP address to multiple servers, and  
   (2) uses standard BGP to advertise this address from each of the servers.

   <br/>

    - When a router receives multiple route advertisements for this IP address,  
      it treats them as providing different paths to the same physical location.
    - In reality, they are different paths to different physical locations.

    <br/>


2. While configuring its routing table, each router runs the `BGP route-selection algorithm` to pick the best route to that IP address.

<br/>

After this initial BGP address-advertisement phase, the CDN can do its main job of distributing content.

3. When a user requests a video, the CDN returns to the user **the common IP address shared by** the geographically dispersed servers,  
   no matter where the user is located.


4. When the user sends a request to that address, Internet routers forward the request packet to the "closest" server, as defined by the BGP route-selection algorithm.

<br/>

In practice, CDNs generally don't use IP anycast as in the example above, because BGP routing changes can cause packets  
belonging to the same TCP connection to arrive at different instances of the replicated web server.

The DNS system, on the other hand, makes extensive use of IP anycast to direct DNS queries to the closest root DNS server.

<br/>
<br/>

## 5.4.5 Routing Policy

When a router selects a route to a destination,  
`AS routing policy` takes precedence over all other considerations, such as shortest AS-PATH or hot potato routing.

<br/>

In the figure below, six `autonomous systems (ASs)`, **A, B, C, W, X, and Y**, are interconnected.

- **W, X, Y** are `access ISPs`


- **A, B, C** are `backbone provider networks`
    - They send traffic directly to each other.
    - They provide full BGP information to their customer networks.

<br/>

<p align="center"><img width="640" alt="BGP policy" src="https://user-images.githubusercontent.com/86337233/213658073-8398ac03-a290-49be-8260-696b19d42110.png">

<br/>
<br/>


---

<br/>

> All traffic `entering` an ISP access network **must be destined for that network,**  
> and all traffic `leaving` an ISP access network **must have originated in that network.**

- **W and Y** are clearly access ISPs.
- **X** is called a `multi-homed access ISP`, since it's connected to the rest of the network via two different providers.

<br/>

Like W and Y, **X** itself must be the destination or source of all traffic entering or leaving it.

Implementing and enforcing this access-network behavior, and preventing X from forwarding traffic between B and C,  
can be done by **controlling how BGP routes are advertised**.

<br/>

That is, **X** advertises to its neighbors B and C that **it has no paths to any destinations other than itself.**  
(Even if X knows of a path, say XCY, to Y, it doesn't advertise this path to B)

So since B is unaware that X has a path to Y, B will never forward traffic destined for C or Y to X.

<br/>

---

<br/>

Suppose **provider network B** has learned (from A) that A has a path `AW` to W.

B can then install the route AW into its routing information table,  
and it will want to advertise the path `BAW` to its customer **X**, so that X knows it can route to W via B.

<br/>

> But should B advertise the path `BAW` **to C as well**?

If it did, **C** could route traffic to W via that path,  
but if A, B, and C are all backbone providers, **B would naturally feel it shouldn't have to bear the burden of carrying traffic between A and C**.

<br/>

There's currently no official standard for how backbone ISPs route among themselves,

but a rule of thumb followed by commercial ISPs is that  
**any traffic flowing across an ISP backbone network must have either a source or a destination (or both) in a network that is a customer of that ISP**.

Individual peering agreements have traditionally been negotiated between pairs of ISPs and are often confidential.

<br/>
<br/>

## Why Are There Different Inter-AS and Intra-AS Routing Protocols?

The answer lies in the differing goals of `intra-AS routing` and `inter-AS routing`.

<br/>

### Policy

`Inter-AS routing` is dominated by policy issues.

It may well be important that traffic originating in a given AS not be able to pass through another specific AS,  
and it's equally natural for a given AS to want control over what traffic it carries between other ASs.

<br/>

On the other hand, `within a single AS`, **everything is under the same administrative control**, so policy issues play a much less important role in choosing routes.

<br/>

### Scale

In `inter-AS routing`, the ability of a routing algorithm and its data structures to handle routing to and among huge numbers of networks is a critical issue.

<br/>

Within `a single AS`, on the other hand, scalability is less of a concern.

If a single ISP becomes too large, it can be split into two ASs, with inter-AS routing performed between the two new ASs.  
(OSPF also allows a hierarchy to be built by splitting an AS into multiple areas)

<br/>

### Performance

Since `inter-AS routing` is policy-oriented, the quality (e.g., performance) of the routes used is only a secondary concern.

Within `a single AS`, such policy considerations matter little, so routing can focus more on the level of performance achieved on a route.

<br/>

## 5.4.6 Putting the Pieces Together: Obtaining Internet Presence

*This section isn't really about BGP per se,*  
*but it brings together many of the protocols and concepts we've seen so far, including IP addressing, DNS, and BGP.*

<br/>

Suppose you've just started a small company.

The company has a number of servers, including a public web server describing its products and services, a mail server, and a DNS server.

<br/>

1. First, you need to get Internet connectivity by contracting with a `local ISP`.
    - Your company will have a `gateway router`, which will be connected to a router in the local ISP.
    - The local ISP will provide you with a range of `IP addresses`. (e.g., a /24 address range consisting of 256 addresses)
    - Once you have the physical connectivity and the IP address range,  
      you assign IP addresses (from your address range) to your web server, mail server, DNS server, gateway router, and other servers and networking devices.

<br/>

2. To obtain a `domain name` for your company (e.g., xanadu.com), you contract with an Internet registrar and register it in the `DNS system`.
    - You need to provide the registrar with the IP address of your `DNS server`.
    - The registrar then adds an entry for your DNS server (domain name and corresponding IP address) to the `.com top-level domain servers`.

<br/>

3. So that people can look up your web server's IP address,  
   your `DNS server` needs to include entries that map the `host name of your web server` (e.g., `www.xanadu.com`) to its `IP address`.  
   (You'll want similar entries for the company's other publicly available servers, including the mail server.)

    - If someone named Alice wants to visit your web server,
        1. the DNS system contacts your DNS server to find the IP address of your web server
        2. and gives it to Alice.
    - Alice can then establish a TCP connection directly with your web server.

<br/>

4. To let outsiders from around the world access your web server,  
   `routers` need to know about the existence of your company's 24-bit `IP address prefix` (or some other length entry) covering your address range.
    - Example scenario
        1. Alice, having learned your web server's IP address, sends an IP datagram (e.g., a TCP SYN segment) to that IP address.
        2. The datagram is routed through the Internet, passing through a series of routers in many different ASs, and eventually reaches your web server.
            - When each of these routers receives the datagram,  
              it looks up the corresponding entry in its `forwarding table` **to determine which output port to send it to**.
    - This is accomplished through `BGP`.
        - When your company contracts with a local ISP and gets assigned an address prefix (i.e., an address range),  
          the local ISP uses BGP to advertise your address prefix to the ISPs it connects with.
        - Those ISPs, in turn, use BGP to propagate the advertisement.
