# 1.1 What Is the Internet?

There are two broad ways to answer that question.

1. Describe the basic **hardware and software components** that make up the Internet (1.1.1)
2. Describe **the Internet as a networking infrastructure** that provides services to distributed applications (1.1.2)

<br/><br/>

## 1.1.1 The Internet as Its Components

The figure below shows the components of the Internet.
<p align="center"><img width="450" alt="Components of the Internet" src="https://user-images.githubusercontent.com/86337233/210067671-04ad6d39-45fc-4ba9-a773-d964ec4cdc7c.png">

<br/>

### Internet

- **Network of Networks**
- A computer network connecting billions of computing devices around the world

<br/>

### Host, End System

- A computing device connected to a computer network
- e.g., servers (desktop PCs, Linux workstations, web servers, etc.) and every "thing" connected to the Internet (TVs, smartwatches, etc.)
- Connected by a network of `communication links` and `packet switches`.

<br/>

### Communication Link

- Transmits `packets (= data)` at various `transmission rates (link bandwidth)`.
- Unit of transmission rate: **bps (bits per second)**
- Made up of various physical media, including coaxial cable, copper wire, optical fiber, and radio spectrum.

<br/>

### Packet

- Sent from the sending end system to the receiving end system (the destination).
- The sending end system **splits the data it wants to send into `segments`**, attaches a `header` to each segment, and sends them to the receiving end system.
- Packets are **reassembled into the original data at the destination.**

<p align="center"><img width="700" alt="Packet" src="https://user-images.githubusercontent.com/86337233/210068063-a8ef4bad-6b44-4d54-8975-7488c2b0acd6.png">

<br/>

### Packet Switch

- Takes a packet arriving on one of its incoming communication links and **forwards it out on one of its outgoing communication links.** (It forwards the packet toward its final destination.)
- The two main types
    - `link-layer switch`: usually used in access networks
    - `router`: usually used in the network core

<br/>

### Route, Path

- The sequence of communication links and packet switches a packet **passes through on its way from the sending end system to the receiving end system**.
- **A packet follows a path through the computer network.**

<br/>

### ISP (Internet Service Provider)

- A network made up of packet switches and communication links
- Provides end systems with various kinds of network access (home broadband, high-speed LAN access, mobile wireless access, etc.)
- Provides Internet access to CPs (content providers) → lets them connect websites and video servers directly to the Internet.
- Interconnection of ISPs
  > 💡 Since the Internet is about connecting end systems to each other, **the ISPs that provide access to end systems must be connected to each other too.**
    - Lower-tier ISPs are interconnected through national and international upper-tier ISPs.
    - Upper-tier ISPs are connected directly to each other.
    - Each ISP network is managed independently, runs the IP protocol, and follows naming and address assignment conventions.

<br/>

### Protocol

- Controls the sending and receiving of information on the Internet.
- The two most important protocols are collectively called **TCP/IP**.
    - `TCP (Transmission Control Protocol)`
    - `IP (Internet Protocol)`: specifies the format of packets sent and received between routers and end systems.

<br/>

### Standards

- IETF (Internet Engineering Task Force)
    - The international Internet standards body
    - RFC (Requests for Comments): IETF standards documents
    - Define protocols such as TCP, IP, HTTP, and SMTP
- IEEE 802 LAN Standards Committee
    - Specifies the Ethernet and wireless Wi-Fi standards

<br/><br/>

## 1.1.2 The Internet as a Service

### The Internet Is an Infrastructure That Provides Services to Applications

- Applications are called `distributed applications` because they involve many end systems exchanging data with each other.
- **Internet applications run on end systems**, not on the packet switches in the network core.

> 💡 **Packet switches** make it easy to exchange data between end systems, but **they don't care about the applications that are the source and sink of that data.**

<br/>

### Socket Interface

```
Q.
How do you tell the Internet to deliver data from an application running on one end system to a program running on another end system?
```

The specification of **how a program running on one end system asks the Internet infrastructure** to deliver data to a specific destination program on another end system is called the `socket interface`.

→ Every end system connected to the Internet has a socket interface.

> 💡 The socket interface is **a set of rules the sending program must follow**, and the Internet delivers data to the destination program according to those rules.

<br/><br/>

## 1.1.3 What Is a Protocol?

For two or more communicating entities to do something together, **they need a protocol, i.e., a set of communication rules, that they all recognize.**

The figure below shows a human protocol and a computer network protocol.

<p align="center"><img width="550" alt="A human protocol and a computer network protocol" src="https://user-images.githubusercontent.com/86337233/210089593-aff053d6-b57c-45c4-ad06-f209a11a0e3a.png">

- Sending and receiving messages, and the actions taken when sending and receiving them, are the heart of a protocol.
- So if one side uses a different protocol, the two sides can't interact and can't get the job done.

<br/>

### Network Protocols

- **Every activity on the Internet that involves two or more communicating remote entities is governed by a protocol.**
- e.g.,
    - `congestion-control protocols`: live on end systems and regulate the rate at which packets are sent between sender and receiver.
    - Protocols in routers: determine a packet's path from source to destination.

> 💡 A protocol defines not only the format and order of messages exchanged between two or more communicating entities, but also the actions taken on sending/receiving a message or on other events.
