# 5.6 The Internet Control Message Protocol (ICMP)

The `Internet Control Message Protocol (ICMP)` is used by hosts and routers to communicate network-layer information to each other.

<br/>

ICMP is often considered part of IP, but **architecturally it sits just above IP**, since ICMP messages are carried inside IP datagrams.

That is, ICMP messages are **carried as IP payload**,  
and when a host receives an IP datagram with ICMP specified as the upper-layer protocol (upper-layer protocol number 1), it demultiplexes the contents to ICMP.

<br/>

ICMP messages have `type and code fields`,  
and they contain the header and the first 8 bytes of the IP datagram that caused the ICMP message to be generated.

This lets the sender identify the packet that caused the error.

<br/>
<br/>

The important ICMP message types are shown below.

> 💡 ICMP messages aren't used only to signal error conditions.

### The ping program

1. Sends an `ICMP message with type 8, code 0` to the specified host.
2. Seeing the echo request, the destination host sends back an `ICMP echo reply with type 0, code 0`.

Most TCP/IP implementations support the ping server directly in the operating system.  
(That is, the ping server isn't a separate process.)

<br/>

### The source quench message

The original purpose of this message was to perform congestion control.

That is, **a congested router sends an `ICMP source quench message` to a host to make it slow down its transmission rate**.

<br/>

However, we saw earlier that TCP has its own congestion-control mechanism that operates at the transport layer,  
without network-layer feedback such as ICMP source quench messages, so this message is rarely used in practice.

<br/>

### The Traceroute program

In the following way, the source host learns the number and identities of the routers between itself and the destination host, as well as the round-trip time between the two hosts.

<br/>

1. **To determine the names and addresses of the routers between the source and destination,**  
   Traceroute at the source sends a series of `IP datagrams` to the destination.
    - Each datagram carries a **UDP segment** with a UDP port number.
    - The TTL is 1 for the first datagram, 2 for the second, 3 for the third, and so on.


2. The source starts a timer for each datagram.
    - When the nth datagram arrives at the nth router, that router observes that the datagram's TTL has just expired.


3. Following the IP protocol rules, the router discards the datagram and sends an `ICMP warning message (type 11, code 0, TTL expired)` to the source.
    - This warning message includes the router's name and IP address.


4. When this ICMP message arrives at the source, the source obtains  
   (1) the round-trip time (RTT) from the timer, and  
   (2) the address and name of the nth router from the ICMP message.

<br/>
<br/>

*How does the Traceroute source know when to stop sending UDP segments?*

1. Because the source increments the TTL by 1 for each datagram it sends,  
   one of these datagrams will eventually make it all the way to the destination host.


2. Since this datagram contains a UDP segment with an unlikely UDP port number,  
   the destination host sends a `port unreachable ICMP message (type 3, code 3)` back to the source.


3. When the source host receives this ICMP message, it knows it doesn't need to send any more probe packets.
