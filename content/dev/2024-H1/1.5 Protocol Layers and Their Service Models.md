# 1.5 Protocol Layers and Their Service Models

<br/>

# 1.5.1 Layered Architecture

A layered architecture lets us discuss a specific, well-defined part of a large and complex system, and that simplification is extremely valuable.

<br/>

When a system has a layered structure, it's also much easier to change the implementation of the service a layer provides.

Even if one layer's implementation changes, the rest of the system stays the same.

<br/>

> 💡 Each layer in a layered architecture provides its service by **(1) performing certain actions within that layer and (2) using the services of the layer directly below it**.

<br/>
<br/>

## Protocol Layering

To provide structure to the design of network protocols,  
network designers organize protocols (and the network hardware and software that implement them) in `layers`.

In other words, **each protocol belongs to one of the layers**, and a protocol layer can be implemented in software, in hardware, or in a combination of the two.

<br/>

- A layer cares about the <b>services</b> it offers to the layer above, which is called the layer's `service model`.
- **Each layer performs certain actions within itself and/or uses the services of the layer directly below it.**

<br/>

Taken together, the protocols of the various layers are called the `protocol stack`.

<br/>
<br/>

## The Internet Protocol Stack

**The Internet protocol stack consists of five layers.**

> Physical, link, network, transport, and application layers

*Layer 1 through layer 5, from the bottom up*

<br/>
<br/>

### Application Layer

> 💡 Where network applications and their application-layer protocols reside.

- The Internet's application layer includes protocols such as:
    - HTTP: provides web document requests and transfers
    - SMTP: provides transfer of e-mail messages
    - FTP: provides file transfer between two end systems
- The `Domain Name System (DNS)` lives in the application layer.
- Application-layer protocols are distributed over multiple end systems,  
  and an application in one end system uses the protocol to exchange `packets of information (messages)` with an application in another end system.

<br/>

### Transport Layer

> 💡 Provides the service of transporting application-layer messages between the client and the server.

- Transport-layer packet = `segment`
- There are two transport protocols, and **both carry application-layer messages.**
    - `TCP`
        - Provides a **connection-oriented service** to its applications.
        - Includes **guaranteed delivery** of application-layer messages to the destination and <b>flow control (matching the sender's and receiver's speeds)</b>.
        - Breaks long messages into shorter segments and provides a **congestion-control mechanism** (throttles the source's transmission rate when the network is congested).
    - `UDP`
        - Provides a **connectionless service** to its applications.
        - **Provides no reliability, no flow control, and no congestion control.**

<br/>

### Network Layer (= IP Layer)

> 💡 Responsible for routing `datagrams (IP's unit of transmission)` from one host to another.

That is, it routes datagrams through a series of packet switches (routers, in the Internet) between the source and the destination.

1. In the source host, the Internet transport-layer protocol (TCP or UDP) **passes a transport-layer segment and a destination address to the network layer**.
2. The network layer then provides the service of **delivering the segment to the transport layer in the destination host**.

<br/>

> The network layer has the `IP protocol`, which defines the fields in the IP datagram
**as well as how end systems and routers act on these fields.**

- There is only one IP protocol.
- Every Internet component that has a network layer must run the IP protocol.

<br/>

> The Internet's network layer also contains **routing protocols**.

- `Routing protocols` determine the routes datagrams take between source and destination.
- The Internet is a network of networks, and within a network, the network administrator **can run any routing protocol they want.**

<br/>

### Link Layer

> 💡 Moves entire frames from one network element to an adjacent network element.

Link-layer packet = `frame`

<br/>

> To move a packet **from one node (host or packet switch) to the next node** on the route, the network layer relies on the services of the link layer.

1. At each node, the network layer passes the datagram down to the link layer,
   **which delivers the datagram to the next node along the route.**
2. At that next node, the link layer passes the datagram up to the network layer.

<br/>

The services provided by the link layer depend on the specific link-layer protocol employed over the link.

e.g., some protocols provide reliable delivery from the transmitting node, over one link, to the receiving node on the other end. *(This is different from TCP's reliable delivery service.)*

Because a datagram traverses several links on its way from source to destination, **it may be handled by different link-layer protocols on different links along its route.**

<br/>

### Physical Layer

> 💡 Moves the individual bits within a frame from one node to the next.

The protocols in this layer depend on the link, and further on the link's actual transmission medium (twisted-pair copper wire, single-mode fiber optics, etc.).

<br/>
<br/>

### Routers and Link-Layer Switches

- Both are `packet switches`.
- Like end systems, routers and link-layer switches organize their networking hardware and software into layers.
- But they don't implement all of the layers; **they typically implement only the bottom layers.**  
  (In the figure, the link-layer switch implements layers 1 and 2, and the router implements layers 1 through 3.)
- So Internet routers can implement the IP protocol (a layer 3 protocol), but link-layer switches can't.

<br/>

### Hosts

Hosts implement all five layers.

> 💡 The Internet architecture keeps much of its complexity at the "edges" of the network.

<br/>
<br/>

## Encapsulation

> 💡 At each layer, a packet has two types of fields: `header fields` and a `payload field`.

The payload is typically a packet from the layer above.

<br/>

### The Encapsulation Process

1. At the sending host, an `application-layer message (M in the figure above)` is passed to the transport layer.
2. In the simplest case, the transport layer appends `transport-layer header information (Ht)` to the message, which will be used by the receiver-side transport layer.

<br/>

> `Transport-layer segment` = application-layer message + transport-layer header information

- The transport-layer segment **encapsulates** the application-layer message.
- The transport-layer header information includes:
    - Information that lets the receiver-side transport layer deliver the message to the right application
    - Error-detection bits that let the receiver determine whether the bits in the message have been changed

<br/>

3. The transport layer passes the segment to the network layer.
4. The network layer adds its own header information (Hn), such as the source and destination end system addresses, creating a `network-layer datagram`.

<br/>

5. The datagram is passed to the link layer.
6. The link layer adds its own header information as well, creating a `link-layer frame`.

<br/>

---

<br/>

_The encapsulation process can be more complex than described above._

A large message may be divided into multiple transport-layer segments, and each segment may in turn be divided into multiple network-layer datagrams.

**The receiving side then has to reconstruct each segment from its constituent datagrams.**
