# 3.2 Multiplexing and Demultiplexing

> 💡 **Transport-layer multiplexing and demultiplexing**  
> The process of extending the `host-to-host delivery service` provided by the network layer  
> into a `process-to-process delivery service` for applications running on the hosts

<br/>

1. At the destination host, the transport layer receives `segments` from the network layer just below it.
   > The transport layer is **responsible for delivering the data in these segments** to the appropriate application process running on the host.

<br/>

2. The transport layer delivers the segment (data) to an intermediary, a `socket`.
    - A process, as part of a network application, has sockets.
    - A socket serves as **the door through which data passes** from the network to the process and from the process to the network.
    - Each socket has a unique identifier, its `port number`.

```
Q. How is a received transport-layer segment directed to the right socket?
```

Each transport-layer segment has a **set of fields** in it,  
and the transport layer examines these fields to identify the receiving socket, then directs the segment to that socket.

<br/>

### ✅ Demultiplexing

The job of **delivering the data in a transport-layer segment to the correct socket**.

<br/>

### ✅ Multiplexing

1. Gathering data chunks from sockets at the source host,
2. encapsulating each chunk with header information to create segments,
3. and **passing those segments to the network layer.**

<br/>

### Two Requirements for Transport-Layer Multiplexing

1. Sockets have **unique identifiers**. (= port numbers)
2. Each segment has **special fields that indicate the socket to which it should be delivered**.
    - `source port number field`
    - `destination port number field`

    <br/>
    <p align="center"><img width="270" alt="Fields" src="https://user-images.githubusercontent.com/86337233/211320125-ff37b76f-2ad8-43d8-9b1a-56872c592a5c.png">

<br/>

### How the Demultiplexing Service Works

1. Each socket in the host is assigned a port number.
2. When a segment arrives at the host,
    1. the transport layer **examines the destination port number** in the segment,
    2. and directs the segment to the corresponding socket.
3. The segment's data then passes through the socket to the attached process.

This is essentially how UDP works.

<br/>
<br/>

## Connectionless Multiplexing and Demultiplexing

> 💡 A UDP socket is fully identified by a two-tuple consisting of a `destination IP address` and a `destination port number`.

So if two UDP segments have **the same destination IP address and destination port number**,  
they'll be directed to the same process via the same destination socket.

<br/>

So what is the **source port number** for?

> The `source port number` serves as part of a <b>"return address"</b>.

<br/>

As the figure below shows, when B wants to send a segment back to A,  
**the destination port number in the segment from B to A** is **taken from the source port number** of the segment from A to B.

## Connection-Oriented Multiplexing and Demultiplexing

### TCP Sockets

> 💡 A TCP socket is identified by a `four-tuple`.

- Source IP address
- Source port number
- Destination IP address
- Destination port number

<br/>

In particular, two arriving TCP segments with **different source IP addresses or different source port numbers** will be directed to two different sockets.  
_(except for a TCP segment carrying the initial connection-establishment request)_

<br/>

### TCP Connection Establishment

1. The TCP server application has a `welcoming socket`.  
   This socket **waits for connection-establishment requests from TCP clients** on `port number 12000`. _(see the figure below)_

    <br/>
    <p align="center"><img width="500" alt="TCP" src="https://user-images.githubusercontent.com/86337233/211320130-8033e75c-8713-4db2-9ecb-be5768fab8a8.png">
    <br/><br/>


2. The TCP client **creates a socket and sends a** `connection-establishment request segment`.
    - The connection-establishment request is sent as a TCP segment with `destination port number 12000` and a special connection-establishment bit set in the TCP header (covered in Section 3.5).
    - The segment also includes a `source port number`, chosen by the client.


3. When the host operating system of the computer running the server process receives the incoming connection-request segment with `destination port 12000`,  
   it hands the segment to **the server process waiting to accept a connection on port number 12000.**


4. The server takes note of the four-tuple in the connection-request segment.
   > A server host can support many simultaneous TCP sockets.
    - **The newly created connection socket is identified by the four values of the four-tuple.**
    - So any subsequently arriving segment whose source port, source IP address, destination port, and destination IP address **all match**  
      will be demultiplexed to this socket.

<br/>
<br/>

## Web Servers and TCP

> 💡 The server distinguishes segments sent by different clients by their `source IP address` and `source port number`.

<br/>

Let's look at an example of **two clients using the same destination port number (80)** to communicate with the same web server application.

- **Host C starts two HTTP sessions** to server B
- **Host A starts one HTTP session** to server B

<br/>

<p align="center"><img width="700" alt="Communicating with a web server application" src="https://user-images.githubusercontent.com/86337233/211320137-5c90b955-b4b2-4dcb-ab04-8f25e6b24d2e.png">

<br/>
<br/>

Host A, host C, and server B **each have their own unique IP address: A, C, and B respectively.**

- Host C assigns two different source port numbers (26145 and 7532) to its HTTP connections.
- Because host A chooses source port numbers independently of host C,  
  **it might also assign 26145 as the source port for its HTTP connection.**

<br/>

> Even so, server B can still demultiplex correctly, **because the two connections have different source IP addresses.**

<br/>

---

<br/>

A web server spawns a new `process` for each connection.

Each of these **processes has its own** `connection socket`, through which HTTP requests arrive and HTTP responses are sent.

<br/>

> However, there isn't always a one-to-one correspondence between connection sockets and processes.

- Many of today's high-performance web servers use only one process.
- They create a new `thread` with a new connection socket for each new client connection.

<br/>
<br/>

## Persistent & Non-persistent HTTP

### Persistent HTTP

For the lifetime of a persistent connection, the client and server exchange HTTP messages **through the same server socket**.

<br/>

### Non-persistent HTTP

A new TCP connection is created and closed for every request/response.
