# 5.1 Introduction

The `forwarding table` (for destination-based forwarding) and the `flow table` (for generalized forwarding) were the key elements linking the network layer's data plane and control plane,  
and these tables specified forwarding in a router's local data plane.

Recall the figures from the previous chapter.

<br/>
<br/>


<p align="center"><img width="700" alt="Forwarding table 2" src="https://user-images.githubusercontent.com/86337233/213144144-816658f9-54f9-4782-afc5-016e19310c12.png">

With generalized forwarding, the actions a router takes could take many forms:

- Forwarding a packet to one of the router's output ports
- Dropping or duplicating a packet
- Rewriting layer 2, 3, and 4 header fields

<br/>

In this chapter, we'll look at **how forwarding tables and flow tables are computed, maintained, and installed**.

<br/>

### Per-Router Control

> 💡 Individual routing algorithms interact with each other in the control plane.

<br/>

The figure below shows the case where a routing algorithm runs in **each and every** router.

<br/>

<p align="center"><img width="700" alt="Per-router control" src="https://user-images.githubusercontent.com/86337233/213144138-0baa9de9-c18c-4349-ad2a-6198a6dce222.png">

<br/>
<br/>

- Both the forwarding and routing functions are contained within each individual router.
- Each router has a routing component that **communicates with the routing components in other routers**
  to compute the values of its own forwarding table.
- The `OSPF` and `BGP` protocols are based on this per-router control approach.

<br/>

### Logically Centralized Control

> 💡 A distinct, typically remote, controller interacts with local control agents (CAs).

<br/>

The figure below shows the case where a `logically centralized controller` computes the forwarding tables and distributes them for use by every individual router.

<br/>

<p align="center"><img width="700" alt="Logically centralized control" src="https://user-images.githubusercontent.com/86337233/213144125-6428c97b-0b2c-4579-8074-dc12785f9361.png">

<br/>
<br/>

Thanks to the generalized '`match plus action`' abstraction,  
a router can perform traditional IP forwarding as well as a variety of functions that used to be implemented in separate devices (load balancing, firewalling, NAT).

<br/>

The controller interacts with a `control agent (CA)` in each router via a protocol to configure and manage that router's flow table.

Unlike per-router control, the CAs don't interact directly with each other, nor do they actively take part in computing the forwarding table.
