# 3.1 Introduction and Transport-Layer Services

> A transport-layer protocol provides `logical communication` between application processes running on different hosts.

= From the application's perspective, it `looks as if the hosts running the processes were directly connected`.

<br/>

As the figure below shows, transport-layer protocols are **implemented in the end systems**, not in network routers.

<br/>

<p align="center"><img width="450" alt="Logical communication" src="https://user-images.githubusercontent.com/86337233/211300154-5efb3c66-2ccb-4388-a301-df582a4ac1f5.png">

<br/>
<br/>

1. On the `sending side`, the transport layer converts the messages it receives from the sending application process into **transport-layer packets**.  
   (These are called `transport-layer segments`: `L4-PDU`)
    1. It breaks the application messages into smaller chunks.
    2. It adds a transport-layer header to each chunk.


2. The transport layer **passes the segment to the network layer at the sending end system.**
    - The segment is encapsulated within a network-layer packet (a `datagram`: `L3-PDU`) and sent to the destination.

   > Network routers act only on the network-layer fields of the datagram.  
   > In other words, they don't examine the fields of the transport-layer segment encapsulated inside the datagram.


3. On the `receiving side`, the network layer extracts the transport-layer segment from the datagram and **passes the segment up to the transport layer.**


4. The transport layer then processes the received segment, making the data in it available to the receiving application.

<br/>

A network application can use **more than one transport-layer protocol**.

e.g., the Internet has two protocols: TCP and UDP.

<br/>
<br/>
<br/>

# 3.1.1 Relationship Between Transport and Network Layers

> 💡 A `transport-layer protocol` provides logical communication between **processes** running on different hosts.

> 💡 A `network-layer protocol` provides logical communication between **hosts**.

- Transport-layer protocols live in the end systems,  
  and their job is to move messages between application processes and the network layer.
- *They don't deal with how messages move within the network layer.*  
  In other words, whoever is dealing with the application (writing or running it) doesn't need to worry about the physical connections that will carry it.

<br/>

1. The services a transport layer can provide are **constrained by the service model of the underlying network-layer protocol.**

   > e.g.,  
   > If the network-layer protocol can't provide **delay or bandwidth guarantees** for transport-layer segments sent between hosts,  
   > then the transport-layer protocol can't provide delay or bandwidth guarantees for messages sent between processes.

<br/>

2. Certain services can still be offered by a transport protocol even when the underlying network protocol doesn't offer the corresponding service.

   > e.g.,  
   > Even when the underlying network protocol is unreliable, the transport layer can provide a reliable data transfer service to the application.  
   > (Unreliable = it may lose, corrupt, or duplicate packets)

<br/>
<br/>
<br/>

# 3.1.2 Overview of the Transport Layer in the Internet

## TCP & UDP

### Transmission Control Protocol, TCP

- Provides a **reliable**, **connection-oriented** service. (reliable data transfer)
- **Congestion control**: on a congested network link, it lets each TCP connection share the link's bandwidth fairly.

<br/>

### User Datagram Protocol, UDP

- Provides an **unreliable**, **connectionless** service.
- An application using UDP as its transport protocol can send at whatever rate it pleases, for as long as it pleases.

<br/>
<br/>

## Segments and Datagrams

- `Segment`: the term for a **transport-layer packet**
- Some sources call a TCP packet a `segment` and a UDP packet a `datagram`.

*This book refers to both TCP and UDP packets as **segments**, and uses the term **datagram** for network-layer packets.*

<br/>
<br/>

## Internet Protocol (IP)

The Internet's network-layer protocol

> The IP service model is a `best-effort delivery service` that provides logical communication between hosts.

<br/>

That is, IP makes its "best effort" to deliver segments between communicating hosts, but **makes no guarantees.**

- No guarantee of segment delivery
- No guarantee of ordering
- No guarantee of the integrity of the data inside

→ IP is an `unreliable service`.

<br/>

> 💡 Every host has at least one IP address.

<br/>
<br/>

## The UDP and TCP Service Models

### Transport-Layer Multiplexing and Demultiplexing

> 'host-to-host delivery' → 'process-to-process delivery'

They extend IP's delivery service between end systems / into a **delivery service between two processes** running on those end systems.

<br/>

### Error-Detection Fields in the Header

These provide `integrity checking`.
