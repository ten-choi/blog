# 5.2 Routing Algorithms

> 💡 The goal of a `routing algorithm`: determine a <b>good path (route)</b> from the sender to the receiver through the network of routers

<br/>

Typically, a "good" path is the <b>least-cost path</b>.

In practice, though, real-world concerns such as **network policy** also come into play.  
(e.g., router x, which belongs to organization Y, should not forward packets originating from a network owned by organization Z)

<br/>

### Graphs

A **graph** is used to formulate routing problems.

<p align="center"><img width="400" alt="Graph" src="https://user-images.githubusercontent.com/86337233/213212557-7f4721cc-104d-4102-9c13-b4d45e4ae79d.png">

<br/>
<br/>

Graph, `G(N, E)`

- `N`
    - A set of nodes
    - In the context of network-layer routing, the `nodes` in the graph represent **routers**, the points at which packet-forwarding decisions are made.


- `E`
    - A set of edges
    - In the context of network-layer routing, the `edges` in the graph represent **the physical links between routers**.
    - Each edge has a value representing its **cost**.  
      (Typically reflecting the physical length of the link, the link speed, or the monetary cost associated with the link)
    - For any edge (x, y) in E, `c(x, y)` denotes the cost between nodes x and y.
    - If edge (x, y) belongs to E, node y is said to be a <b>neighbor</b> of node x.


- An edge is represented as a pair of nodes from the set N.

<br/>

A <b>path</b> in graph G(N, E) is a sequence of nodes (`x1, x2, x3, …, xp`)  
such that each of the pairs `(x1, x2), (x2, x3), … , (xp-1, xp)` is an edge in E.

The cost of a path (x1, x2, x3, … , xp) is simply the sum of all the edge costs along the path.  
`c(x1, x2) + c(x2, x3) + … + c(xp-1, xp)`

<br/>
<br/>

## Classifying Routing Algorithms

<br/>

One common way to classify routing algorithms is by whether they are `centralized` or `decentralized`.

### Centralized routing algorithm

> 💡 Computes the least-cost path between a source and destination **using complete, global knowledge about the network**.

The computation itself can be performed at one site or replicated in the routing module of every router.

Algorithms with global state information are called `link-state (LS) algorithms`,  
since the algorithm must be aware of the cost of each link in the network.

<br/>

### Decentralized routing algorithm

The least-cost path is computed by the routers in an iterative, distributed manner.

> 💡 Each node starts out **knowing only the costs of its own directly attached links**.

Then, through an iterative process of calculation and exchanging information with its neighbors, a node gradually computes the least-cost path to a destination or set of destinations.

Decentralized routing algorithms are also called `distance-vector (DV) algorithms`,  
because each node maintains a vector of estimates of the costs (distances) to all other nodes in the network.


<br/>

---

<br/>


A second common way to classify routing algorithms is as `static` or `dynamic`.

### Static routing algorithm

Routes change very slowly over time, often as a result of human intervention (e.g., a person manually editing a link cost).

<br/>

### Dynamic routing algorithm

Changes routing paths as network traffic loads or topology change.

A dynamic algorithm can be run periodically or in direct response to topology or link cost changes.

- Pros: responds quickly to network changes.
- Cons: more susceptible to problems such as routing loops and route oscillation.

<br/>

[Note] Topology: the physical arrangement of the elements of a computer network (links, nodes, etc.), or the way they are connected

<br/>

---

<br/>

A third way to classify routing algorithms is by whether they are `load-sensitive or not`.

### Load-sensitive algorithm

Link costs vary dynamically **to reflect the current level of congestion on the link**.

If a high cost is assigned to a currently congested link, the routing algorithm will tend to choose routes around that congested link.

Early ARPAnet routing algorithms were load-sensitive, which caused a number of difficulties.

<br/>

### Load-insensitive algorithm

Today's Internet routing algorithms (RIP, OSPF, BGP, etc.) are load-insensitive, since a link's cost doesn't explicitly reflect its current (or most recent) level of congestion.

<br/>

## 5.2.1 The Link-State (LS) Routing Algorithm

> In a link-state algorithm, **the network topology and all link costs are known**, so they are available as input to the LS algorithm.


This is accomplished by having each node **broadcast** `link-state packets`, containing the identities and costs of its directly attached links,  
**to all other nodes in the network**,

which is often done by a `link-state broadcast algorithm`, such as the Internet's OSPF routing protocol.

<br/>

### Dijkstra's algorithm

> 💡 Dijkstra's algorithm computes the least-cost path from one node (the source, referred to as `u`) to all other nodes in the network.

After the **k-th iteration** of the algorithm, the least-cost paths are known to k destination nodes,  
and among the least-cost paths to all destination nodes, these k paths have the k smallest costs.

<br/>

Notation

- `D(v)`: **the cost of the least-cost path** from the source node to `destination v` as of the current iteration of the algorithm
- `p(v)`: **the previous node** (neighbor of v) along the current least-cost path from the source to v
- `N’`: a subset of nodes

v is in N’ if the least-cost path from the source to v is definitively known.

<br/>

### Link-state (LS) algorithm for source node u

### Forwarding table

When the LS algorithm terminates, we know, for each node, its predecessor along the least-cost path from the source node.

`Node u's forwarding table` is built by storing, for each destination, the next-hop node on the least-cost path from u to that destination.

### Computational complexity

Given `n nodes (not counting the source)`, how much computation must be done in the worst case to find the least-cost paths from the source to all destinations?

In the first iteration, we need to search through all **n** nodes to determine the node w, not in N’, that has the minimum cost;  
in the second iteration, we need to check **n-1** nodes; in the third iteration, **n-2** nodes; and so on.

So the total number of nodes searched is `n(n+1)/2`,  
which gives the link-state algorithm a worst-case complexity of `O(n^2)`.

<br/>
<br/>

One way to prevent such oscillations is to ensure that **not all routers run the LS algorithm at the same time**.

This seems like a reasonable approach: even if routers run the LS algorithm with the same period,  
the execution instant of the algorithm wouldn't be the same at each node.

<br/>

However, researchers found that even when routers initially run the algorithm at different start times but with the same period,  
**they eventually become synchronized with each other**.

This `self-synchronization` can be avoided by having each node randomize the time at which it sends out its link-state advertisements.

## 5.2.2 The Distance-Vector (DV) Routing Algorithm

*The algorithm actually used in practice today is the distance-vector (DV) routing algorithm.*

<br/>

Whereas the LS algorithm uses global network information,  
the distance-vector algorithm is **iterative, asynchronous, and distributed**.

- `Distributed`: each node receives information from one or more of its directly attached neighbors, performs a calculation, and then distributes the results back to its neighbors.
- `Iterative`: the process continues until no more information is exchanged between neighbors.
- `Asynchronous`: the nodes don't need to operate in lockstep with each other.

<br/>

### The Bellman-Ford equation

The cost of the least-cost path from node x to y can be expressed as follows.

<br/>

<p align="center"><img width="500" alt="Bellman-Ford equation" src="https://user-images.githubusercontent.com/86337233/213212603-bad1ae1e-7838-4623-b3dc-226725c24f1a.png">

- min.v is taken over all of x's neighbors.
- If we travel from x to v and then take the least-cost path from v to y, the path cost will be `c(x, v) + d.v(y)`.
- Since we must begin by traveling to some neighbor v,
- the least cost from x to y is `the minimum of c(x, v) + d.v(y)` taken over all neighbors v.

<br/>

The solution to the Bellman-Ford equation provides the entries in each node's forwarding table.

- Let `v*` be the neighbor node that achieves the minimum in the equation above.
- If **node x wants to send a packet to node y** along a least-cost path, it should forward the packet to node v*.

So **node x's forwarding table** should specify `v*` as the next-hop router for the ultimate destination y.

<br/>

---

<br/>


So the basic idea of the distance-vector routing algorithm is as follows.

> Assuming x is the source node, node x estimates D.x(y), the cost of the least-cost path from itself to every other node y in N.

<br/>

Let D.x be the vector of cost estimates from x to all other nodes y in N.

With the DV algorithm, each `node x` maintains the following routing information.

- For each neighbor v, **the cost to each directly attached neighbor**, `c(x, v)`

1. Each node waits for an update from any neighbor *(lines 10–11)*,

### The distance-vector (DV) algorithm: link-cost changes and link failure

When a node running the DV algorithm

1. detects a change in the cost of the link from itself to a neighbor,
2. it updates its distance vector, and
3. **if there's a change in the cost of the least-cost path**, it sends its new distance vector to its neighbors.

<br/>

Let's look at both cases: when the least-cost path's cost decreases and when it increases.

<br/>

#### a. When the cost decreases

Below is the case where the cost of the link from y to x changes from 4 to 1.

<p align="center"><img width="320" alt="Cost decrease" src="https://user-images.githubusercontent.com/86337233/213214090-baa35d20-b8c1-495e-b82d-c877001f6737.png">

<br/>
<br/>


In this scenario, the DV algorithm causes the following sequence of events.

1. Time t0: `y` detects the link-cost change, updates its distance vector, and informs its neighbors of this change.


2. Time t1: `z` receives the update from y and updates its table.
    - z computes a new least cost to x.
    - It sends its new distance vector to its neighbors.


3. Time t2: `y` receives z's update and updates its table.
    - **y's least costs haven't changed, so y doesn't send any message to z.**
    - The algorithm then comes to a quiescent state.

<br/>

So the DV algorithm needs only two iterations to reach a quiescent state.

<br/>

#### b. When the cost increases

Below is the case where the cost of the link from y to x changes from 4 to 60.

<br/>

In this scenario, the DV algorithm causes the following sequence of events.

1. Time t0: `y` detects the link-cost change and computes a new least-cost path to node x with the following cost.

   <br/>

    <p align="center"><img width="930" alt="Cost increase calculation" src="https://user-images.githubusercontent.com/86337233/213214096-1af1855b-1116-49ac-8873-1943c7727dc5.png">
    <br/><br/>

    - Since we can see the whole network at a glance, we can tell that this new cost via z is **wrong**,  
      but node y can't.


2. Time t1
    - A `routing loop` occurs: to get to x, y routes through z, and z routes through y.

      > If a packet destined for x arrives at y or z at t1, it will bounce back and forth between these two nodes until the forwarding tables change.

    - Since node y has computed a new minimum cost to x, it informs z of its new distance vector.


3. Time t2: z receives y's update and computes a new least cost.
    - D.z(x) = min{50+0, 1+6} = 7
    - Since z's least cost to x has increased, it informs y of its new distance vector.


4. Time t3: y receives z's new distance vector and computes a new least cost.
    - Dy(x) = min{60+0, 1+7} = 8
    - Since y's least cost to x has increased, it informs z of its new distance vector.


5. …

<br/>

This endlessly repeating problem is known as the `count-to-infinity` problem.

<br/>

### Distance-vector algorithm: adding poisoned reverse

The specific looping scenario just described can be avoided using a technique called `poisoned reverse`.

<br/>

That is, if z routes through y to get to destination x, **then z advertises to y that its distance to x is infinity.**

*z keeps telling this little lie to y as long as it routes to x via y.*

Since y then believes z has no path to x,  
y will never attempt to route to x via z as long as z continues to route to x via y.

<br/>

**However, poisoned reverse doesn't solve the general count-to-infinity problem.**

Loops involving three or more nodes, rather than simply two directly neighboring nodes, won't be detected by poisoned reverse.

## Comparing the Link-State and Distance-Vector Routing Algorithms

### ✅ How paths are computed

The LS and DV algorithms take contrasting approaches to computing routes.

<br/>

#### LS algorithm

- Requires global information.
- Each node talks with **all** other nodes (via broadcast).
- It tells them **only** the costs of its directly connected links.

<br/>

#### DV algorithm

- Each node talks **only** with its directly connected neighbors.
- It provides its neighbors with least-cost estimates from itself to **all** the nodes (that it knows about) in the network.

<br/>

### ✅ Message complexity

#### LS algorithm

- Each node needs to know the cost of each link in the network, which requires `O(|N| |E|)` messages to be sent.
- Whenever a link cost changes, the new link cost must be sent to all nodes.

<br/>

#### DV algorithm

- Messages are exchanged between directly connected neighbors at each iteration.
- The time it takes for the algorithm to converge depends on many factors.
- When link costs change, the DV algorithm propagates the changed link cost only if the new link cost results in  
  a changed least-cost path for one of the nodes attached to that link.

<br/>

### ✅ Robustness

What happens if a router fails, misbehaves, or is sabotaged?

<br/>

#### LS algorithm

- A router could broadcast an incorrect cost for one of its attached links.
- A node could corrupt or drop any packets it receives as part of an LS broadcast.

But **since an LS node computes only its own forwarding table**,  
route calculations are somewhat separated under LS.

So the LS algorithm provides a degree of robustness.

<br/>

#### DV algorithm

- A node can advertise incorrect least-cost paths to any or all destinations.

At each iteration, a node's DV calculation is passed on to its neighbors, and then indirectly to its neighbors' neighbors on the next iteration.

So in a network using the DV algorithm, an incorrect calculation at one node **can spread through the entire network.**

<br/>

In fact, in 1997 a malfunctioning router at a small ISP provided national backbone routers with erroneous routing information.

This caused other routers to flood the malfunctioning router with traffic,  
and large portions of the Internet were reportedly disconnected for several hours.

<br/>

---

<br/>

In the end, neither algorithm is an obvious winner over the other,  
and in fact both algorithms are used in the Internet.
