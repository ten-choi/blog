# 2.7 Socket Programming: Creating Network Applications

To create a network application, you write two programs: a client program and a server program.

When you run them, two processes are created, and they communicate with each other by reading from and writing to sockets.

<br/>
<br/>

There are two kinds of client-server applications.

<br/>

> 1️⃣ A client-server application that implements a standard protocol defined in an RFC, such as HTTP

When implementing this kind of application, you must use the port number associated with that protocol.

<br/>

> 2️⃣ A proprietary network application that uses an application-layer protocol not officially published in an RFC or elsewhere

Other independent developers won't be able to write code that interoperates with this application. When implementing it, be careful not to use any of the well-known port numbers.

The developer also needs to choose between TCP and UDP, taking each protocol's characteristics into account.

<br/>
<br/>
<br/>

# 2.7.1 Socket Programming with UDP

With UDP, before the sending process can push a packet of data out the socket door, it must first attach a destination address to the packet.

After the packet passes through the sender's socket, the Internet uses that destination address to route the packet to the receiving process's socket.

When the packet arrives at the receiving socket, the receiving process retrieves it through the socket, inspects its contents, and takes the appropriate action.

<br/>
<br/>

## Destination Address

Including the destination address in the packet lets routers in the Internet route the packet through the Internet to the destination host.

Each host is identified by its `IP address`.

<br/>

However, since a host may be running many network application processes, each with one or more sockets,  
**we also need to identify a particular socket within the destination host.**

When a socket is created, an identifier called a `port number` is assigned to it.

So the packet carries a destination address made up of an IP address and a port number, along with the sender's source address (IP and port).

<br/>

Attaching these addresses is normally done automatically by the underlying operating system.

<br/>
<br/>

## Socket Programming

<p align="center"><img width="600" alt="UDP application" src="https://user-images.githubusercontent.com/76640167/210794628-43c23c47-34d8-4a5b-b5e4-d7d617cdcf90.png">

The figure above shows the main socket-related activities of a client and server communicating over UDP.

1. The client reads a line of characters from the keyboard and sends the data to the server.
2. The server receives the data and converts the characters to uppercase.
3. The server sends the modified data back to the client.
4. The client receives the modified data and displays the line on its screen.

We'll build a simple client-server application that works in this order.

<br/>

### UDPClient.py

When creating the socket, you don't need to specify its port number; the operating system takes care of that for you.

```
# The socket module. It lets us create sockets.
from socket import *

# Set the server's IP address or hostname.
serverName = 'hostname'

# The destination port number.
serverPort = 12000

# Create the client socket. AF_INET means we're using IPv4, and SOCK_DGRAM means it's a UDP socket.
clientSocket = socket(AF_INET, SOCK_DGRAM)

# Read the message to send.
message = input('Input lowercase sentence:')

# To send it through the socket as bytes, first convert it to the bytes type with encode().
# The sendto() method attaches the destination address to the message and sends the packet into the process's socket, clientSocket.
# The client's address is sent along too, and that happens automatically.
clientSocket.sendto(message.encode(),(serverName, serverPort))

# The packet data is stored in modifiedMessage, and the packet's source address (IP, port) is assigned to serverAddress.
# recvfrom() reads with a buffer size of 2048.
modifiedMessage, serverAddress = clientSocket.recvfrom(2048)

# Print
print(modifiedMessage.decode())

# Close the socket
clientSocket.close()
```

<br/>

### UDPServer.py

Thanks to the while loop, the server keeps waiting for the next UDP packet to arrive even after one exchange is done.

```
from socket import *

# Port number
serverPort = 12000

# Create a UDP socket
serverSocket = socket(AF_INET, SOCK_DGRAM)

# Bind port 12000 to the socket. Now any packet sent to port 12000 at the server's IP address is delivered to this socket.
serverSocket.bind(('', serverPort))

print("The server is ready to receive")

while True:
    # When a packet arrives at the server, its data is assigned to message and its source address is stored in clientAddress.
    # That address tells the server where to send its reply.
    message, clientAddress = serverSocket.recvfrom(2048)
    
    # Decode the bytes and convert them to uppercase.
    modifiedMessage = message.decode().upper()
    
    # Attach the client's address to the uppercased message and send the resulting packet back to the client.
    # The server's address is sent along too, and that happens automatically.
    serverSocket.sendto(modifiedMessage.encode(), clientAddress) 
```

# 2.7.2 Socket Programming with TCP

`TCP` is a **connection-oriented protocol**, so the two sides need to establish a TCP connection before they can send data to each other.

When the TCP connection is created, the client socket address and the server socket address are associated with the connection.

Once the connection is established, you just send data into the TCP connection through the socket.

<br/>
<br/>

## Welcoming Socket and Connection Socket

<p align="center"><img width="450" alt="TCP" src="https://user-images.githubusercontent.com/76640167/210809355-8e26c0e0-561c-45bc-ba57-8d34487c68bc.png">

With the server process running, the client process initiates a TCP connection to the server, which it does by **creating a TCP socket in the client program**.

When creating the TCP socket, the client specifies the address (IP, port #) of the server's `welcoming socket`.

After creating the socket, the client goes through a 3-way handshake to establish a TCP connection with the server. (The handshake is completely invisible to the programs.)

<br/>

During the handshake, the server creates **a new socket dedicated to that particular client**. This is called the `connection socket`.

From the application's perspective, the client's socket and the server's connection socket are directly connected by a pipe.

Through the pipe, the client can send arbitrary bytes into its socket, and TCP guarantees that the server process will receive them. The same goes in the other direction.

<br/>
<br/>

## Socket Programming

The figure above shows the typical structure of a client-server TCP connection.

Let's write programs that do exactly the same thing as the UDP version.

<br/>

### TCPClient.py

The comments focus on what's different from UDP.

```
from socket import *

serverName = 'servername'
serverPort = 12000

# The client socket. SOCK_STREAM specifies that it's a TCP socket.
# As with UDP, we don't specify the source address. (The OS handles it for us.)
clientSocket = socket(AF_INET, SOCK_STREAM)

# Before the client can send data to the server over a TCP socket, a TCP connection must first be set up between them.
# This line initiates the TCP connection; the parameter of connect() is the server-side address of the connection.
# After this line runs, the 3-way handshake is performed and a TCP connection is established between client and server.
clientSocket.connect((serverName, serverPort))

sentence = input('Input lowercase sentence:')

# Send into the TCP connection through the client socket. Unlike a UDP socket, we don't explicitly create a packet or attach a destination address to it.
# Instead, the client program simply drops the bytes of the string into the TCP connection.
clientSocket.send(sentence.encode())

# Wait to receive bytes from the server.
modifiedSentence = clientSocket.recv(1024)
print('From Server: ', modifiedSentence.decode())

# Close the connection. This causes the client's TCP to send a TCP message to the server's TCP.
clientSocket.close()
```

<br/>

### TCPServer.py

```
from socket import *

serverPort = 12000

# Create a TCP socket
serverSocket = socket(AF_INET, SOCK_STREAM)

# Associate the server's port number with the socket.
serverSocket.bind(('', serverPort))

# The bound socket now listens, waiting for a client to knock on the door.
# The parameter is the maximum number of queued connections.
serverSocket.listen(1)
print('The server is ready to receive')

while True:
    # When a client requests a TCP connection, accept() is invoked, creating a connection socket on the server for that client.
    # The client and server then complete the handshake, creating a TCP connection between the client's socket and the connection socket.
    connectionSocket, addr = serverSocket.accept()
    sentence = connectionSocket.recv(1024).decode()
    capitalizedSentence = sentence.upper()
    connectionSocket.send(capitalizedSentence.encode())
    
    # Send the reply and close the connection socket. The welcoming socket, serverSocket, stays open, so other clients can still request connections to the server.
    connectionSocket.close()
```
