일본에 있는 사내 공용어가 영어인 IT 기업(메루카리, 페이페이, 라쿠텐, LINE야후, Indeed, Woven by Toyota, 스마트뉴스 등)에 백엔드/소프트웨어 엔지니어로 지원할 때의 일반적인 프로세스 정리. 회사마다 세부 단계는 다르지만 큰 틀은 대부분 비슷하다.

전체 기간은 보통 **4주 ~ 8주** 정도. 빠르면 2~3주 만에 끝나는 곳도 있다.

---

## 0차. 서류 전형 (Resume Screening)

- **영문 이력서(Resume)** 제출. 일본 기업이지만 영어 공용어 회사는 일본식 이력서(履歴書/職務経歴書)가 아니라 영문 레주메 1~2장을 요구하는 경우가 대부분.
- LinkedIn 프로필, GitHub, 기술 블로그 링크가 있으면 플러스.
- 리크루터를 통한 지원(referral 포함)이 서류 통과율이 확실히 높다.
- 소요: 3일 ~ 2주

## 0.5차. 온라인 코딩 테스트 (Online Assessment) ※ 있는 회사도, 없는 회사도 있음

- HackerRank, Codility, CoderPad 등 플랫폼에서 진행.
- 알고리즘/자료구조 문제 1~3문제, 60~120분.
- 난이도는 LeetCode 기준 Easy ~ Medium 수준이 대부분.
- 이 단계가 리크루터 콜보다 먼저 오는 회사도 있다.
- 지원자가 많은 큰 회사(라쿠텐, 페이페이, 리크루트/Indeed 등)일수록 초반 필터로 돌리는 경우가 많고, 리퍼럴 지원이나 시니어 포지션이면 건너뛰는 경우도 꽤 있다.

## 1차. 리크루터 스크리닝 (Recruiter Screening / Casual Interview)

- HR 또는 리크루터와 30분 정도 화상 통화.
- 내용: 경력 소개, 지원 동기, 희망 연봉, 비자 상태, 입사 가능 시기, 일본어/영어 레벨 확인.
- 기술 질문은 거의 없고, 기본적인 커뮤니케이션이 되는지 보는 단계.
- **영어로 진행되는 경우가 많으므로 자기소개(1~2분)와 경력 요약은 영어로 미리 준비해둘 것.**
- 회사에 따라 "카주얼 면담(カジュアル面談)"이라는 이름으로 합불 판정 없이 진행하기도 한다.

## 2차. 기술 인터뷰 1 - 라이브 코딩 (Technical Interview: Coding)

- 엔지니어 1~2명과 60분 내외.
- CoderPad, HackerRank 라이브 등에서 실시간으로 코드를 작성.
- 알고리즘/자료구조 문제를 풀면서 **사고 과정을 영어로 말하는 것(think aloud)** 이 중요.
- 정답 여부만큼 커뮤니케이션, 엣지 케이스 처리, 시간/공간 복잡도 분석을 본다.
- 회사에 따라 이 단계가 2회(코딩 x2)인 곳도 있다.
- **온라인 코테와 달리 라이브 코딩은 영어 공용어 회사 기준 거의 100% 있다고 보면 된다.** 코드 실력 자체보다 영어로 소통하면서 문제를 푸는 능력을 보려는 목적이라, 자동 채점으로 대체가 안 되기 때문.
- 그래서 혼자 조용히 푸는 연습보다 **말하면서 푸는 연습**이 중요하다. 문제 이해 확인 → 접근법 설명 → 코딩하면서 중계 → 복잡도 설명, 이 흐름을 영어로 몸에 익혀둘 것.
- 예외적으로 테이크홈 과제로 대체하는 소규모 스타트업도 있지만, 그런 곳도 과제 리뷰 세션에서 결국 코드에 대해 영어로 설명해야 해서 준비 방향은 같다.

### 사용 언어

- 온라인 코테/라이브 코딩 모두 **언어 자유 선택**이 기본. 언어를 강제하는 경우는 드물다.
- 라이브 코딩에서는 회사 스택에 맞추기보다 **가장 편한 언어**를 쓰는 게 정답. 어색한 언어로 문법에서 버벅이면 얻는 것보다 잃는 게 크다.
- 예외: 포지션 특화 테이크홈 과제는 해당 스택(예: Go 백엔드면 Go)을 지정하기도 한다. 채용 공고나 리크루터가 미리 알려줌.
- **나는 Java로 진행.** 라쿠텐, LINE야후는 실무 스택도 Java라 자연스럽고, 다른 회사에서도 전혀 문제없다.

### 코테 출제 유형 (2024~2026 실제 후기 기준)

최근 2년 내 면접 후기(문서 하단 근거 링크)를 기준으로 정리. 결론부터: **Easy 단독 출제는 드물다.** Easy는 OA 첫 문제나 라이브 웜업(첫 5~10분)으로만 등장하고, 합불을 가르는 건 Medium + 팔로업이다. 시니어 포지션은 동시성·실무형 구현까지 올라간다.

**회사별 최근 실태**

| 회사 | 온라인 코테 | 라이브 코딩 / 온사이트 |
|---|---|---|
| 라쿠텐 | Codility 2~3문제, Easy~Medium. 해시맵·이진 탐색·문자열이 주요 토픽 | Medium 1문제 60분 (2025 후기). Java 내부 동작(GC, 메모리, Stream lazy evaluation) 질문 병행 |
| 메루카리 | 2024-11 후기: 감독형 OA로 **Hard 2문제** (우선순위 큐, DP, 비트 조작 기반). 인턴/신졸은 E·M·H 3문제 60분 | 시니어는 테이크홈(200k RPS pub/sub API, 8시간) + 리뷰 세션 사례 |
| 페이페이 | Codevue(HackerRank식) 4문제 easy→hard. 슬라이딩 윈도우, 괄호 문제 보고됨 | 루프 4세션 중 2개에 코딩 포함: 기초 지식(GC, 데이터 레이스) + LeetCode 15분, DSA 최적화 라운드 |
| LINE야후 | Codility 5문제 3시간, 그중 2~3개 Medium (2024-11 후기) | IM 시스템 설계 + **동시성 태스크 풀 구현** — "일반 DSA보다 어렵다"는 평 |
| Indeed | 별도 OA 없이 Karat 라이브로 대체 | Karat 외주: **Medium 3문제 60분, 2문제 이상 통과**. 쉬운 문제 → 팔로업 → 어려운 팔로업 구조. 그래프 BFS/DFS 빈출 |

**1순위 — 라이브 코딩의 중심 (전부 Medium)**

- **그래프/그리드 BFS·DFS** (Indeed Karat 빈출, 라이브 최다 보고 유형): 200 Number of Islands / 994 Rotting Oranges / 542 01 Matrix / 1091 Shortest Path in Binary Matrix / 133 Clone Graph / 207 Course Schedule
- **슬라이딩 윈도우 / 투 포인터** (페이페이 OA 보고): 3 Longest Substring Without Repeating Characters / 424 Longest Repeating Character Replacement / 209 Minimum Size Subarray Sum / 15 3Sum / 11 Container With Most Water
- **해시맵** (라쿠텐 OA 주요 토픽): 560 Subarray Sum Equals K / 128 Longest Consecutive Sequence / 49 Group Anagrams / 347 Top K Frequent Elements
- **이진 탐색** (라쿠텐 OA 주요 토픽): 33 Search in Rotated Sorted Array / 153 Find Minimum in Rotated Sorted Array / 875 Koko Eating Bananas / 34 Find First and Last Position

**2순위 — OA 후반부(Medium~Hard)·팔로업에서 등장**

- **힙/우선순위 큐** (메루카리 OA 출제 보고): 215 Kth Largest Element [M] / 23 Merge k Sorted Lists [H] / 295 Find Median from Data Stream [H]
- **DP** (메루카리 OA 출제 보고): 322 Coin Change [M] / 198 House Robber [M] / 53 Maximum Subarray [M] / 300 Longest Increasing Subsequence [M]
- **인터벌/정렬**: 56 Merge Intervals [M] / 253 Meeting Rooms II [M] / 435 Non-overlapping Intervals [M]
- **트리**: 98 Validate BST [M] / 236 Lowest Common Ancestor [M] / 102 Level Order Traversal [M]
- **모노토닉 스택**: 739 Daily Temperatures [M] / 84 Largest Rectangle in Histogram [H]

**웜업/OA 첫 문제용 (Easy) — 5분 안에 풀고 지나가는 용도, 여기에 시간 쓰지 말 것**

- 1 Two Sum / 20 Valid Parentheses (페이페이 괄호 문제의 기본형) / 242 Valid Anagram / 704 Binary Search / 226 Invert Binary Tree / 121 Best Time to Buy and Sell Stock

**DSA 밖에서 나오는 것들 (시니어일수록 비중↑)**

- **동시성 구현**: LINE야후의 태스크 풀 구현이 대표 사례. LeetCode Concurrency 카테고리(1114 Print in Order, 1115 Print FooBar Alternately)로 감 잡고, Java `ExecutorService`/`BlockingQueue`로 스레드 풀 직접 구현해볼 것.
- **설계형 구현 문제**: 146 LRU Cache [M] / 362 Design Hit Counter [M] — "자료구조를 조합해 컴포넌트를 만들어라" 유형.
- **테이크홈**: 스케일 요구사항이 명시된 API 구현 (메루카리 200k RPS pub/sub 사례).
- **언어 내부 지식**: 라쿠텐·페이페이 모두 Java GC, 메모리 관리, 데이터 레이스 질문 보고. Java로 가면 이 부분은 코테와 별도로 준비 필수.

**플랫폼 주의점**

- 페이페이 Codevue는 LeetCode와 달리 **stdin에서 직접 입력을 파싱**해서 stdout으로 출력하는 방식. Java `BufferedReader`로 입력 파싱을 빠르게 하는 연습이 필요하다.
- Codility(라쿠텐, LINE야후)는 LeetCode보다 공개 테스트 케이스가 적어서 엣지 케이스 감점이 크다는 후기. 빈 입력/경계값을 스스로 챙겨야 한다.

**Java로 풀 때 미리 손에 익혀둘 것**

- `HashMap`/`HashSet`의 `getOrDefault`, `computeIfAbsent`, `merge`
- `ArrayDeque`(스택·큐 겸용), `PriorityQueue`(comparator 지정 포함)
- `Arrays.sort` + 커스텀 `Comparator`, `Collections.sort`
- `StringBuilder`(문자열 조작은 무조건 이걸로), `String.split`/`charAt`/`substring`
- 2차원 그리드 BFS 템플릿 (방향 배열 `{{0,1},{0,-1},{1,0},{-1,0}}` + visited)

## 3차. 기술 인터뷰 2 - 시스템 디자인 (System Design Interview)

- 시니어 엔지니어와 60분 내외.
- "URL 단축 서비스를 설계하라", "채팅 시스템을 설계하라" 같은 오픈엔드 설계 문제.
- 요구사항 정리 → 대략적 아키텍처 → DB 설계 → 스케일링/트레이드오프 순으로 진행하는 게 정석.
- 주니어~미들 레벨이면 이 단계가 생략되거나 가볍게 진행되기도 하고, 시니어 이상이면 비중이 크다.
- 도메인에 따라 코딩 대신 실무형 과제(테이크홈 과제 + 리뷰 세션)로 대체하는 회사도 있다.

### 회사별 시스템 디자인 실태 (2024~2026 후기 기준)

공통 경향: "URL 단축기 설계하라" 같은 교과서형 문제보다 **그 회사 도메인에 붙은 실무형 문제**가 나온다. 근거는 문서 하단 링크.

| 회사 | 출제 방식 | 실제 보고된 문제/주제 |
|---|---|---|
| 라쿠텐 | 별도 라운드 + OA에 설계 문제 1개가 섞여 나온 사례도 있음 | "대용량 파일을 이동시키는 아키텍처", "광고 CTR 예측 시스템 설계" (2024~25 후기). 아키텍처 패턴·설계 원칙 심층 질문 + DB 설계, 네트워킹, HTTP 버전 차이 같은 세부 지식 병행 |
| 메루카리 | 독립 라운드보다는 EM과의 1시간+ 세션에서 시스템 디자인 + DBMS + 문제 해결을 통합 평가. 테이크홈(200k RPS pub/sub) 자체가 설계 평가를 겸함 | 분산 시스템 경험을 명시적으로 중시. 과거 프로젝트의 규모(스케일)를 깊게 파는 방식 |
| 페이페이 | 루프 내 시스템 디자인 라운드 + 도메인 지식 라운드 분리 | **결제 도메인 직결**: "천만 동시 사용자 캐싱 전략", "초당 10만 건 금융 트랜잭션 처리 아키텍처", "사용자가 Pay 버튼을 연타하면?" → 멱등성 키·rate limiting (2025-06 후기). 모놀리스 vs MSA, SQL vs NoSQL, ACID 심층 질문 병행 |
| LINE야후 | 1차 기술 면접이 곧 시스템 디자인. 온라인 화이트보드로 설계+코딩 (공식 구조화 면접) | **IM(메신저) 시스템 설계** — 헤드카운트 있는 팀에 따라 주제가 바뀜 (2024-11 후기). 자사 서비스(LINE)를 그대로 설계시키는 패턴 |
| Indeed | 풀데이 온사이트 중 1세션이 시스템 디자인, 별도로 코드 리뷰 세션과 progex(실무형 프로그래밍 과제)도 있음 | 화이트보드 코딩 2 + 시스템 디자인 1 + 코드 리뷰 1 + 레주메 딥다이브 1 구성 보고 |

**준비 포인트**

- **지원 회사의 도메인 문제를 미리 설계해볼 것.** 페이페이면 결제(멱등성, 이중 결제 방지, 원장 정합성), LINE야후면 메신저(WebSocket, 메시지 전달 보장, 읽음 상태 동기화), 라쿠텐/메루카리면 커머스(검색, 재고, 주문 트래픽 스파이크). "그 회사 대표 서비스를 설계하라"가 반쯤 예상 문제다.
- 공통 기본기: 캐싱 전략, DB 샤딩/레플리케이션, 메시지 큐, 멱등성, 백오브엔벨롭 계산(QPS·스토리지 추정).
- 설계 라운드에서도 DBMS 세부(인덱스, 트랜잭션 격리 수준)와 네트워크(HTTP/1.1 vs 2 vs 3) 같은 지식 질문이 병행된다는 후기가 라쿠텐·페이페이 양쪽에서 반복됨. 순수 그림 그리기 연습만으로는 부족하다.

## 4차. 최종 인터뷰 - 매니저 / 컬처핏 (Final: Hiring Manager & Behavioral)

- 채용 매니저(HM), 팀 리드, 경우에 따라 VP/CTO와 45~60분.
- 행동 기반 질문(Behavioral): "갈등을 해결한 경험", "실패한 프로젝트와 배운 점", "왜 일본에서 일하고 싶은가" 등.
- **STAR 형식(Situation, Task, Action, Result)으로 답변 준비.**
- 회사의 미션/밸류에 대한 이해를 확인하는 질문이 많으므로(특히 메루카리 계열은 밸류 질문이 유명) 회사 컬처 문서를 미리 읽고 갈 것.
- 역질문(질문 있나요?) 시간도 평가의 일부. 팀/기술스택/온보딩에 대한 질문 2~3개 준비.

## 5차. 오퍼 (Offer & Negotiation)

- 오퍼 레터 제시 → 연봉 협상 → 수락.
- 일본은 연봉을 월급 + 보너스 또는 연봉 일괄(RSU 포함 여부 확인)로 제시하니 총액(현금 + 주식 + 보너스) 기준으로 비교할 것.
- 해외 거주자의 경우 비자 스폰서(기술·인문지식·국제업무 비자 등)와 이주 지원(relocation package) 조건 확인.
- 레퍼런스 체크를 이 시점에 하는 회사도 있다.
