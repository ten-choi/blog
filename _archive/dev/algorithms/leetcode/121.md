# 121. Best Time to Buy and Sell Stock

## Problem

You are given an array `prices` where `prices[i]` is the price of a given stock on the i-th day.
You want to maximize your profit by choosing a single day to buy one stock and choosing a different day in the future to sell that stock.
Return the maximum profit you can achieve from this transaction. If you cannot achieve any profit, return `0`.

**Example**

```
Input:  prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6 - 1 = 5.
```

**Constraints**

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`


## How I'd explain it in an interview

### 1. Clarify the problem

Before coding, I'd confirm a few things with the interviewer:

- We can make **exactly one** transaction: one buy, then one sell.
- The sell day must come **after** the buy day — we can't sell first and buy later.
- If prices only go down, the answer is `0`, not a negative number.
- The array is guaranteed to have at least one element, so `prices[0]` is always safe to read.

### 2. Brute force (and why it's not good enough)

The naive approach is to try every pair `(i, j)` with `i < j` and take the maximum of `prices[j] - prices[i]`.
That's O(n²). With `n` up to 10^5, that's around 10^10 operations, which will time out.
So we need something closer to O(n).

### 3. Key insight

The observation that makes this a one-pass problem:

> At any day `i`, the best profit I can get by **selling today** is
> `prices[i] - (the lowest price I've seen so far)`.

So as I scan left to right, I only need to keep track of **two variables**:

1. `minPrice` – the lowest price seen up to the current day (the best day to buy so far).
2. `maxProfit` – the best profit achievable so far.

For each day I do two things, in this order:

- Update `maxProfit` using the current price and the current `minPrice`.
- Then update `minPrice` if today's price is lower.

The order matters: I update `maxProfit` **before** `minPrice`, so I never "buy and sell on the same day".
If I lowered `minPrice` first, then `prices[i] - minPrice` could be `0` on that same day, which is harmless here but conceptually wrong.

### 4. Walk through the example

`prices = [7,1,5,3,6,4]`

| Day | Price | minPrice (after) | Profit if sold today | maxProfit |
|-----|-------|------------------|----------------------|-----------|
| 0   | 7     | 7                | –                    | 0         |
| 1   | 1     | 1                | 1 - 7 = -6           | 0         |
| 2   | 5     | 1                | 5 - 1 = 4            | 4         |
| 3   | 3     | 1                | 3 - 1 = 2            | 4         |
| 4   | 6     | 1                | 6 - 1 = 5            | **5**     |
| 5   | 4     | 1                | 4 - 1 = 3            | 5         |

Answer: `5`.

## Solution

### Version 1 – explicit `if` statements

```java
class Solution {
    public int maxProfit(int[] prices) {
        int maxProfit = 0;          // Return 0 if no profitable transaction exists.
        int minPrice = prices[0];   // Safe: the array is guaranteed to have at least one element.

        for (int i = 1; i < prices.length; i++) {
            // 1) Best profit if I sell today at prices[i].
            if (prices[i] - minPrice > maxProfit) {
                maxProfit = prices[i] - minPrice;
            }
            // 2) Track the cheapest day to buy so far.
            if (prices[i] < minPrice) {
                minPrice = prices[i];
            }
        }

        return maxProfit;
    }
}
```

### Version 2 – using `Math.max` / `Math.min` (cleaner)

This is the version I'd actually write in an interview. Same logic, but `Math.max` / `Math.min` read more like the sentence "the best profit so far is the max of what I had and what I'd get today".

```java
class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = Integer.MAX_VALUE;  // Alternative initialization: no special-casing prices[0].
        int maxProfit = 0;                 // Best profit seen so far.

        for (int price : prices) {
            maxProfit = Math.max(maxProfit, price - minPrice);  // Sell today?
            minPrice  = Math.min(minPrice, price);              // Or is today a better day to buy?
        }

        return maxProfit;
    }
}
```

Note on `Integer.MAX_VALUE`: on the first iteration `price - minPrice` would overflow in theory, but since `price >= 0` and `minPrice = Integer.MAX_VALUE`, the result is a large negative number that `Math.max(0, ...)` simply ignores — so it's safe here. If I wanted to be extra careful, I'd initialize `minPrice = prices[0]` and start the loop from `i = 1`, as in Version 1.

---

## Complexity

- **Time: O(n)** — a single pass over the array.
- **Space: O(1)** — only two extra integers, regardless of input size.

## Follow-up questions an interviewer might ask

- **"What if you can make multiple transactions?"**
  That's LeetCode 122. You'd sum every positive day-to-day difference (`prices[i] - prices[i-1] > 0`), since you can capture every upward move.
- **"What if you can make at most two (or k) transactions?"**
  That's LeetCode 123 / 188, which needs a DP with a state per number of transactions.
- **"What if there's a transaction fee or a cooldown?"**
  LeetCode 714 / 309 — DP with `hold` / `notHold` states.
- **"Can you return the buy and sell days, not just the profit?"**
  Yes — store the index whenever `minPrice` updates, and record `(buyIndex, i)` whenever `maxProfit` updates.

## Related pattern

This is essentially **Kadane's algorithm** applied to the array of daily differences `prices[i] - prices[i-1]`: the maximum subarray sum of those differences equals the maximum profit. Recognizing that link is a nice thing to mention if there's time.
